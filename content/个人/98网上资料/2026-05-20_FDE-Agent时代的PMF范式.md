# OpenAI、Anthropic 都开始押注 FDE，FDE 才是 Agent 时代的 PMF 范式？

**来源**：https://x.com/i/status/2056660897381425590

**作者**：Kafka

**发布时间**：2026-05-20

---

## 核心事件

2026年5月短短一周，三家AI巨头同时押注FDE：

| 时间 | 事件 |
|------|------|
| 5月4日 | Anthropic 把工程师"嵌"进 FIS，共同设计金融犯罪 AI Agent |
| 5月11日 | OpenAI 成立 OpenAI Deployment Company，首期投入 40 亿美元，收购 Tomoro 带来 150 名 FDE |
| 5月12日 | Google Cloud CEO Thomas Kurian 亲自招"几百个"FDE |

---

## 一、FDE 是什么

**Forward Deployed Engineer，前置部署工程师**。

这个角色由 Palantir 在 2000 年代初发明，当时客户是美国情报机构——"既不能清楚说出自己要什么、也不能让你看他们的数据、工作流程本身还在不断变化"。

Palantir 联合创始人 Shyam Sankar："如果一个问题能被需求文档解决，那它早就被解决了。"

**FDE 的特殊之处**：
- 写客户的生产代码
- 同时把客户场景里发现的共性问题反哺回厂商的核心产品

**对比三种常见角色**：
| 角色 | 特点 |
|------|------|
| 销售工程师 | 售前演示，签完合同就走 |
| 解决方案架构师 | 技术咨询，不写生产代码 |
| 咨询顾问 | 出方法论、做交付，不参与产品迭代 |
| **FDE** | **写生产代码，同时沉淀回产品** |

Palantir 的"砂石路变柏油路"模式：FDE 在客户现场修出无数条砂石路，产品团队找出走的人最多的几条，铺成柏油路，变成平台能力。

---

## 二、2026 年为什么是拐点

三家公司的判断指向同一个事实：**Agent 时代的瓶颈，不在模型本身，而在部署。**

- 埃森哲调研：只有 32% 的企业看到了"持续的企业级 AI 影响"，剩下 68% 有试点、PPT、Demo，但没有规模化交付
- IBM 2026 年调查："执行速度"被列为第三大战略优先级

**OpenAI 的直白表述**："过去几年，超过一百万家企业采用了我们的产品和 API。一个模式越来越清晰——下一阶段企业 AI 的胜负，取决于企业能多有效地把这项技术部署到真实业务场景中。"

**核心逻辑**：模型本身的"产品力"边际收益在下降，但"把模型变成可用系统"的工程能力，边际收益在飙升。

---

## 三、为什么 Agent 时代对 FDE 有"结构性需求"

Agent 和此前 AI 形态的根本区别：

| | 传统 SaaS | Agent |
|--|----------|-------|
| 本质 | 工具——你买模板，人去使用 | 代劳——让它替你做 |
| 边界 | 产品手册写得明白 | 必须深度嵌入客户真实工作流 |
| 失败后果 | 功能失败——用户抱怨 | 业务失败——银行被监管罚款 |

**三个后果**：
1. Agent 必须深度嵌入客户的真实工作流——合规边界、数据在哪、SAR怎么写，都不在产品文档里
2. Agent 的失败是业务失败，不是功能失败
3. Agent 市场是"既无成熟产品可对标、客户自己也不知道要什么"的市场——这正是 Palantir 当年面对情报机构时的状况

## 四、三个保留

### 保留一：FDE 可能在"掩盖 PMF 问题"

PMF 的本意是：产品本身就是答案，客户拿来即用、续费、推荐。

如果一个产品需要派一队工程师驻场半年才能跑起来，严格来说，它的产品本身还没有找到 PMF。

**Gartner 预测**：到 2028 年，70% 的企业将被迫放弃由 FDE 主导的 Agent 项目，原因是"厂商成本过高、内部缺乏独立演进的能力"。

"FDE 工作量在多次部署后没有递减，就是依赖性而非能力被构建出来的信号。"

### 保留二：这是不是"伪装成产品公司的咨询公司"？

Palantir 在二级市场长期被低估，因为分析师习惯用纯软件 SaaS 的估值框架套它，套不上。

**OpenAI Deployment Company 的困境**：用 Anthropic 的几率为零。CIO 们会通过"锁定"的视角看这件事。

### 保留三：FDE 可能正在被自己创造的工具替代

FDE 之所以贵，在于他们要做大量的"集成性脏活"：字段映射、API 对接、legacy 系统翻译、提示词调优、评估框架搭建——这些恰恰是 AI 最擅长自动化的。

**但均衡是微妙的**：模型越强，FDE 的价值来源转向"在客户现场判断该解决哪些问题、该把什么标准化"这种业务判断。

## 五、对不同人的意义

| 身份 | 含义 |
|------|------|
| **AI 厂商** | FDE 不是收入业务，是产品发现机制。只有把驻场经验沉淀成可复用产品能力——MCP server、agent skills、评估框架、部署模板——FDE 投入才会有复利 |
| **企业客户** | FDE 的真正价值是"能力转移给你"，不是"帮你建好"。合同里要有退出机制，否则 FDE 模式就是温柔的锁定 |
| **工程师** | 这是 2026 年最稀缺的技能组合：技术深度 + 客户语境理解 + 业务判断力。Google FDE 基薪 12.7-26.5 万美元，资深包平均 23.8 万，顶级接近 40 万 |
| **投资人** | 用纯 SaaS 估值框架套 FDE 驱动的 AI 公司会失真。要看"砂石路变柏油路"的速度 |

---

## 结语

FDE 是 Agent 时代企业级 AI 从 Demo 走向生产系统的"必要中间态"，但它本身不是 PMF——**它是寻找 PMF 的方法**。

2026 年 5 月的 AI 企业市场，有"PMF 的雏形"，但还没有"PMF 的胜利"。

三家公司同时押注 FDE，承认了一个事实：在 Agent 成为真正的"软件之上的软件"之前，我们需要人，需要驻场的人，需要懂客户、也懂模型的人，去把那些没有铺好的路一段一段走通。
