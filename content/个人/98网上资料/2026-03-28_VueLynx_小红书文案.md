# 有人两周时间造了一个 Vue Native 框架！

> 本文基于 Vue Lynx 项目实战经验，分享如何用 AI 驱动完成一个生产级框架的原型开发

---

## 项目背景

Vue 开发者想要原生应用开发能力已经很多年了。

去年 Lynx 开源时，Evan You 和 Rich Harris 都转发了。但生产级框架集成一直需要大量工程投入。直到看到 Vercel 的 web streams 重写和 Cloudflare 的 ViNext 项目 —— 都展示了单个工程师借助 AI 就能交付过去需要一个团队才能完成的工作。

Vue 已经有成熟的基础：Custom Renderer API。通过一个周末的可行性验证。一场 37 小时的黑客马拉松，成本约 1400 美元。

---

## 核心架构决策：双线程 vs 单线程

### 技术选型关键

在动手之前，社区已经有两个尝试。第二个来自 Vue Vine 维护者 @Shenqingchuan，甚至已经跑通了 Main Thread Script 的 demo。但这两个方案都把 Vue 放在主线程，跟 Web 的做法一样。

这在 Lynx 上能跑，但没利用 Lynx 最核心的双线程架构：
- **背景线程（Background）**：运行框架重渲染逻辑
- **主线程（Main Thread）**：保持 UI 非阻塞，只在必要时介入
---
### Vue Lynx 的架构设计

首先在第一天就确定了这个核心架构：

```
Vue Runtime (Background Thread)
    ↓
ShadowElement Tree (内存中的轻量级镜像)
    ↓
Ops Buffer (序列化的 DOM 变更)
    ↓
Main Thread (批量应用，非阻塞 UI)
```

---

**关键代码结构**：
- Vue 完整运行在 Background 线程
- ShadowElement 链表树镜像原生元素树
- 每个 DOM 变更序列化为扁平 ops buffer
- 每帧批量发送到主线程

为了让 AI 始终对齐这个双线程架构，把所有关键设计文档直接嵌入源码树：设计讨论笔记、决策日志、实现后的学习总结都作为跨会话上下文。每次新会话都能继承之前的架构约束和推理过程。

---

## 测试策略：如何验证双线程渲染器

### 复用 Vue 上游测试套件

AI 驱动开发最关键的投资是反馈循环。理想情况下，应该直接复用 Vue 官方测试套件来确保一致性。
但 Vue 的测试假设单线程 DOM。怎么在双线程渲染器上跑这些测试？
**解决方案**：
Lynx 已经有双线程测试环境的基础设施。重新接线，让测试跑完整个双线程管道：

```
BGShadowElement → Ops Buffer → syncFlush() → MTapplyOps → PAPI → jsdom
```

然后让 AI 持续修复直到没有可修复的失败（Ralph Loop）。

---

**结果**：
- 949 个上游测试中 852 个通过
- 每个失败都有记录在 skip list 中，并附原因说明
- 所有失败都是可忽略的边界情况

### Lynx 专属测试覆盖

还补充了 Lynx 特有功能的测试：
- `<list>` 元素
- `bindtap` 事件
- Main Thread Scripting API

### 7GUIs 压力测试

验证完基础管道后，从 Vue 官方文档 fork 了 7GUIs 基准测试作为压力测试。

## Agentic E2E 验证循环

### 传统测试的盲区

经典单元测试无法捕捉真实 UI bug：CSS 布局错位、真机上的交互失效。对于 `<Transition>`、`<Suspense>` 这些高级特性，你需要亲眼看到运行效果才能验证正确性。

### 解决方案：双环境自动化

写示例不只是为了 demo —— 它们同时也是 AI 可以自动评估的工作负载。

**两个执行环境**：
1. **iOS 模拟器**：通过 Lynx DevTool MCP/CLI/Skill 控制
2. **浏览器**：通过 Lynx for Web 的 agent 控制浏览器

---

**验证循环**：
1. 在两种环境运行示例
2. 观察并验证输出
3. 任何回归触发自动修复
4. 无需人工介入

### 核心特性验证流程

先从 Vue 核心特性开始，这里正确性定义明确：
- AI 读取官方文档
- 编写示例代码
- 检查输出是否符合文档描述

然后扩展到生态集成：Vue Router、Pinia、TanStack Query、Tailwind CSS。

---
### 期末考试：差分验证
最后用了另一种方法，后来知道这叫"差分评估"（Differential Evaluation）：

**测试 1：HackerNews 克隆**
- 以 Web 版 Vue HackerNews 实现为基准
- Web 版和 vue-lynx 版并排运行在浏览器中
- AI 对比输出是否一致

**测试 2：ReactLynx Demo 移植**
- 以现有 ReactLynx demo 为参考
- 移植到 vue-lynx
- 在 iOS 模拟器验证行为一致性

**关键洞察**：验证框架不需要知道"正确"长什么样，只需要两个输出一致即可。

## 成本分析：真实的 AI 开发账单

很多人好奇用 Claude 开发这种项目的真实成本。

**Token 消耗分布**：
- 输出 token（AI 实际写的代码和文本）：仅占 8%
- 输入 token（重读代码、处理工具输出、会话历史）：占 92%

**具体数字**：
- 31,700 次 API 调用
- 25 亿输入 token → 680 万输出 token
- **阅读：写作比例 = 370:1**

这就是"agentic"开发在账单层面的真实面貌。

**总成本**：约 6500 美元（Claude 通过开源项目赠送了 200 美元 Claude Max）

## 给你的实操建议

如果你也想尝试类似的 AI 驱动开发：

1. **架构文档内嵌**：把设计决策、约束条件直接写进代码仓库，让 AI 每次都能继承上下文
2. **建立自动化验证闭环**：不要依赖人工测试，写可以被 AI 执行的验证脚本
3. **从核心开始，逐步扩展**：先验证最基础、定义最清晰的功能
4. **利用现有测试套件**：不要从零写测试，想办法复用官方测试
5. **差分验证**：当没有明确标准时，用并行对比来验证正确性
