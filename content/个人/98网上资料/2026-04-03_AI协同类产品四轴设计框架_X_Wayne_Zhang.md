## 核心内容

### 背景：Coding Agent 领域的演进规律

过去一个季度，Coding Agent 领域出现了一条清晰的演进脉络：

1. **底座定义能力边界**：Claude Code 和 CodeX 定义了底座能力
2. **社区探索能力上限**：社区项目（如 oh-my-opencode）引入 Multi-Agent 协同
3. **外围降低使用门槛**：外围项目（如 OpenClaw）通过通信层和网关推动下沉市场采用
4. **官方回收最佳实践**：Opus 4.6 和 CodeX 5.4 将最佳实践重新整合回模型本身

**核心结论：当大多数团队都可以借助 Coding Agent 快速达到自己想要的技术目标时，技术底层本身很难再构成护城河。**

---

### 四轴设计框架

#### 轴1：人机关系——人在场，还是人离场

- **人在场（协同端）**：用户主导决策，AI 辅助执行，交互同步、对话式。代表：Claude Code
- **人离场（自主端）**：任务被充分定义后委托给 Agent，异步自行闭环。代表：Manus

**结构性风险**：人在场 → 人是吞吐瓶颈；人离场 → 错误无人兜底、失控成本高。

#### 轴2：记忆范围——用户级记忆，还是组织级知识

- **用户级记忆**：个人偏好、单次会话上下文。优势：冷启动快、门槛低。问题：信息污染、不可复用
- **组织级知识库**：跨用户、跨 session 持久沉淀。优势：越用越聪明。代价：维护成本高、知识腐化、隐私复杂

**打破默认的产品往往更有意思**：Claude 的 Memory 机制在本地协同场景引入跨 session 个人记忆；很多云端 chatbot 反而是无记忆的一次性交互

#### 轴3：约束方式——Prompt 软约束，还是编码硬约束

- **软约束**：通过自然语言 Prompt 和 System Instruction 实现，弹性高但输出不稳定
- **硬约束**：通过代码脚本、Workflow DAG、规则引擎实现，行为可预测可审计，但僵化

**弱关联轴1**：人在场通常倾向软约束，人离场通常倾向硬约束。但这不是绑定关系

#### 轴4：运行位置——用户端本地，还是公司端云端

- **本地端**：直接触达用户文件系统，数据主权在用户，但难以组织级协同
- **云端**：可连接组织知识库、支持多用户协作，但引入延迟、隐私和供应商锁定

**本质问题**：个人与组织之间如何协同？

---

### 框架应用：如何找差异化

**对任何一款 AI 协同类产品，在四根轴上各标一个位置，四个位置连起来基本就是这款产品的骨架。**

- 点位高度重合的产品是直接竞品，必须在执行层拉开差距
- 点位差异最大的那根轴，才是真正的差异化来源

**以 Claude Code vs Manus 为例**：
- 两者功能层面有重叠
- 但在轴1（人机关系）上处于光谱两端——Claude Code 假设人的判断不可替代，Manus 假设任务可以被充分委托
- **这才是它们之间最本质的区别**

### 关键洞察

> 如果技术趋同是既定方向，那产品之间的实质差异到底来自哪里？

答案是：**产品设计决策**——在四根轴上做出清晰的选择。
