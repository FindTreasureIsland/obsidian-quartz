# 和杨植麟时隔1年的对话：K2、Agentic LLM、缸中之脑和"站在无限的开端"

**张小珺**（商业访谈录主持人）

## 摘要

2025年7月，Kimi K2模型发布引发广泛关注。K2是基于MoE架构的开源编程和Agentic智能体大模型。本文是张小珺商业访谈录对月之暗面创始人兼CEO杨植麟的深度专访，时隔一年半再次对话。

杨植麟借用《无穷的开始》（The Beginning of Infinity）中的核心观点——"问题是不可避免的，但也是可以解决的"——将AI研发比作一场没有终点的雪山攀登。他详细解析了K2如何通过提升Token Efficiency和引入新型优化器突破数据瓶颈，指出AI将从"缸中之脑"式的纯思考转向能够与世界交互的Agent，并揭示从推理到创新的能力阶梯并非线性增长。月之暗面的核心战略是利用更高阶的创新能力去解决Agent的泛化性难题，最终通过AI自我迭代，在动态市场博弈中实现通向AGI的长远目标。

## 一、登山哲学与AGI观

### 1.1 站在无限的开端

**杨植麟**：`有句话要刻在石头上——问题是不可避免的，但问题是可以解决的。`

**杨植麟**：`有可能是无限的山，但我们希望它一直没有尽头，因为这就是所谓的 the beginning of infinity。就是它可能是无限的山，就是你一直在往上爬，而且甚至有可能爬到一段时间之后你不一定是自己在爬，而有可能是你用AI来爬。`

**杨植麟**：`追求就是这个攀登的过程，你能够一直越爬越高。以前我们会固执地认为终点就是AGI。今天的重点已经不是AI了。`

**杨植麟**：`AGI可能是个方向，它可能不是某一集台阶，说你爬到了这集台阶就突然一夜之间达到AI。而是说他可能是一个方向。比如说你今天可能在很多领域其实你可以认为它是AI，因为它可能做的比99%的人类可能都更好。`

**杨植麟**：`AGI跟登月有一个区别——登月就是你到月球那一刻你就达到了，你号称我就达到了。但可能AGI它就不是，它不会有一个明确的时间节点去宣称到达。`

### 1.2 AI发展阶段的感受

**杨植麟**：`可能在大山底下，然后爬到那个又往上提升了一点，然后你能看到的景色会不一样。然后它是一个动态可能进化的过程。`

**杨植麟**：`2023年之后、2024年，我们突然意识到，公司的增长核心是算法、是模型。就是它的底层能力，等于说它躲在产品下面的这层能力，实际上是公司真正的壁垒跟驱动力。`

### 1.3 用AI来爬

**杨植麟**：`比如用K2这个模型去做很多可能模型训练或者说数据处理相关的工作。这些东西它以前可能都是要人写代码，或者有些同学他不一定会写代码但以前就做不了。但是现在比如很多数据处理，或者模型的一些分析，甚至包括模型的一些训练，你慢慢又都可以用这个模型来做。所以你可能就可以把这个东西作为一个放大器，去更好地去做判断。`

## 二、过去一年的关键技术变化

### 2.1 Test-time Scaling

**杨植麟**：`过去一年全球大模型最重要的变化，一个种是强思考的推理模型嘛，基于强思考的强化学习，O1作为第一个做出来的代表。本质上来讲，它通过让模型在这个过程中去做很多的尝试和反思。本质上是两种能力——一种是能力是提出来一个新的猜想，你可以理解为模型在解决一个问题过程中它会不断提出新的猜想，然后这个猜想呢它会得到一个自我的验证。`

**杨植麟**：`实际上跟人做科研或者解题的过程也很像，也就是不断提出新的财然后去验证它。是一个自由探索的过程，它不是一个线性的过程。`

### 2.2 缸中之脑 vs Agentic

**杨植麟**：`这还是一个缸中之脑，就是说他并不需要跟外界交互。缸中之脑——它就是一个想象一个鱼缸，然后你把一个脑子放在里面，它跟这个外界是没有联系的。它只是在自己大脑里面想，它一直想，它不需要跟外界产生任何交互，它就能解一道题。`

**杨植麟**：`但是有另外一个很重要的方式，就是现在可能基于这种多轮的Agent的强化学习的事，或者说通过这种强化学习技术训练出来这种跟Agentic的模型。它的特点是说他会跟外界做很多交互。可能我边思考边去做一些操作。然后我可能做很多轮的这个操作，我一会调用一个搜索，一会使用一下浏览器，一会可能写进行代码。然后我通过多轮的方式解决了问题。那它就不再是缸中之脑，它是可以跟外界交互的。`

### 2.3 Test-time Scaling的两种表现

**杨植麟**：`这两个东西它都指向了同一个东西——都是所谓的test-time scaling。就是你可以是在测试的时候或者说推理的时候做更好的规模化。不管是说把轮数打得更多，还是说在每一轮里面我有更多的这个思考的token，它都是一种去规模化这个token的方式，使得说你能够去完成更复杂的任务。`

**杨植麟**：`你可能现在会花几个小时的时间去做一件很复杂的事情，在这个过程中你可能不需要人工的参与。它就可以比如把一个代码穿龙下来，然后把它翻译成另外一种新的语言，然后去调试测试，然后把所有bug都修了，然后让它能正常运行。这样的一个工作可能是可以端到端地直接完成。得意于这种测试时的这个规模化。`

### 2.4 强化学习的核心依赖

**杨植麟**：`强化学习可能最终还是依赖于一个很好的评估或者很好的验证。比如说你让它去做一个数学题或者一些有testcase的编程，那可能可以做比较好。但是如果你让它去做一个可能更加复杂的端短端的任务，有时候你并不是非常容易找到这个评估或者衡量的方式。`

## 三、K2模型的技术细节

### 3.1 Token Efficiency

**杨植麟**：`K2通过提升代币效率（Token Efficiency）和引入新型优化器来突破数据瓶颈。`

### 3.2 规模化的可预测性

**杨植麟**：`基本上你这个模型是讯式呢怎么样，其实在过程中就已经知道了，就是它并不会说好像有一些惊喜或者惊讶。没有说你的Aha Moment吗？也还好。因为很多东西它是可以被预测的。因为我觉得更重要的是这个预测的能力，因为你这个模型一是需要周期，二是需要有成本的。所以我们希望早期可能多的是把所有能预测都预测到。唯一那个没预测到就是刚说的那个max logic的问题。但那个确实没办法，因为你小规模它就预测不了嘛，对。其他的我觉得都是我们希望尽可能把它预测好的情况。所以你说的东西都是在都是在验证清楚的情况下然后再scale，那你其实scale的成功率是比较高的。`

## 四、Next Token Prediction的局限

**杨植麟**：`我觉得确实，如果你今天不做强化学习，这个模型它很难说很聪明。就像数学题这种，它不一定做得非常好。确实我觉得更大的base，它的强化学习强化学习的上线还是会更高。嗯对，就是因为因为他知识更多，就是本身上是去激活一个推理的尝试，让它能把那个知识解锁出来。嗯，然后把它对，它上线更高。但是你要搭配一个RL去。`

---

## 五、RL与SFT的管理哲学

### 5.1 用RL的方式管理团队

**杨植麟**：`就是发现就是好像管理一个团队他也是这样的方法，就是你是要呃用RL的方式去管理，而不是用SFT。嗯，当然现在你发现好的技术，你说做RL的时候，你其实也希望加一部分SFT。因为SFT是很好的先验，就是所谓的PTX loss。然后你不希望这个模型可能飞太远。但是你要管住自己的手，就是说你不能SFT太多，SFT太多这些同学他就会失去这个主观动生，然后就根本没有办法创新。`

**杨植麟**：`SFT就是你直接给他就是说这个东西应该这样这样做，对吧。然后就是说你给他一个头上而下，就是给他一个奖励。就是说如果做成这样，那它可能是好的。那可能更多时候它是反映在目标上。然后我觉得这两个东西它可能需要一些平衡。然后可能比如说以RL为主，然后通过一部分的SFT去防止它是非太远的。你还是要有些鲜绑去控制或者防止它遗忘掉一些东西。`

### 5.2 Reward的重要性

**杨植麟**：`定这个奖励或者定这个指标，它并不是非常简单的一个事情。就比如说如果你只是最后说我就是要把所有的benchmark做得很高，那你可能会出现很多overfitting的问题。因为你所有人都会不择手段地把那个分子给弄上去。但是弄完之后你发现这个模型好像还没有变好。`

**杨植麟**：`所以这个奖励的定义就很重要，对。或者说说这个奖励的定义也需要你很了解这个具体的细节是怎么运作的，不然的话它就会出现reward hacking。建立一个更多观测指标，尽可能不要去overfitting。这样你才有更好效果，然后不会被hack。`

## 七、Agent产品与模型公司的关系

**杨植麟**：`这个问题我也没有明确的答案。只能说今天看起来，一方面产品有个好处，就是它可以做垂直的整合。因为我可以把模型放在这里面训练，所以我的模型跟工具它是为一体，它不是说分开来做然后再去逆向工程。`

**杨植麟**：`但是因为有非常多的Agent的空间，就是我感觉一方产品不一定做得过对吧？所以有可能如果能找到一些空间，比如说你这个工具的实现它是需要非常多的领域的knowhow，或者说你的evaluation是一方产品根本不会考虑的东西，考虑不过来的东西，那我觉得是有机会的。`

**杨植麟**：`像K2这样的开源的模型，然后就大家可以在上面去微调，让更容易产生出来。也有一些可能是这种 specialized agents 垂直Agent的可能性。我觉得这个可能性还是一定程度上可能会存在的。那要看你通用模型的通用到多少程度了。但不管多用，就是说你总还是有一些工具要做嘛。所以你有可能你也不一定要去做那个模型，而是说你把这个工具做得非常好。`

**杨植麟**：`但是如果你这个工具是做得太通用，你可能就会跟一方的这个产品会overlap，标刀标级会比较大。对，所以这个就是可能你还是做垂直整合优势更大。但是如果说你这个工具是一个我就是专门针对一个东西去做，然后甚至我这个工具是别人做不了的。比如说我今天如果掌握了一些线下服务的入口，那我这个工具就是这个下订单或者成交这个工具是别人根本做不出来的，那你也有可能能够产生一些独特的价值。`

**杨植麟**：`当然我觉得存在另外一种可能性，就是说当你这个一方产品或者说这个通用的Agent，它的流量或者三模式足够成熟之后，你很多这种专有的本来垄断的工具，他也会愿意去接入进来。因为它的整体的商业化效率会更高。`

**杨植麟**：`K2本来就是可能是世界上最难攀登的山峰。刚好这个名字有点重合。这是你归选的这个名字吗？对，但它也是刚好也是G2。就是对我，但我们也希望说那个首先它不是终点对吧？就是因为它不是最高的山峰，它可能是最难的。因为我觉得就是说可能有因为现在有很多范式的转变嘛。你可能从对话到这个Agent，然后可能你的 base model的scale也进一步变大。它本身它肯定存在难度。`

## 九、创业心态

**杨植麟**：`我觉得还是比较简单。就是很多复杂性都是人为强行加上去的，实际上并没有那么复杂。`

**杨植麟**：`肯定不会走弯路的。就像刚才说的，就是你在这个过程中会有很多很多决策，有些是技术决策，有一些是比如说业务的决策。我觉得很重要的一个是说，一个公司在在这个过程中可能去逐渐调整的能力。就像比如说知识创造也是这样的一个过程。就是你不可能创造出来这是所有东西都是对的。`

**杨植麟**：`任何中间状态都会成为被批评的对象。反正类似这个意思吧。就是说我总觉得会有这个时代的局限性。可能更重要的是说，你怎么在这个过程中去投入一些可能一定不变的，就像比如说你的这个人才和技术的积累。然后另一些就是说在这个过程中去去适应和调整，就是你能够针对不管是说是这个反馈信号或者你这个环境的状态变化，然后就去做一些决策。我觉得这两个东西是很重要的。`

**杨植麟**：`我最近一次或者最近两次内自嗨是什么情境啊？为啥为什么呀？我觉得他不以误喜不以杯嘛。这是我说我很难做到。但就是说我觉得这避免一些情绪化的决策。所以你会情绪吗？可能多少肯定会，因为你是一个人嘛。但是就是我说可能避免一些情绪化的决策，最终落实到决策和而和执行上还是要更理性一点。`

## 十、AI与人类文明

**杨植麟**：`人类文明到了一个新节点。就是这个问题当然很重要，就或者说什么问题很重要？呃，就是我觉得AI很重要，就是因为这个问题。我也问过Kim嘛，他跟我说这个东西，他说这个东西是人类文明的放大器。我觉得很有道理。就是从启蒙运动到现在，人类一直在找到新的方法去突破这个知识的边界。但是可能下一个突破边界的确就是要靠AI，因为它是一个巨大的杠杆。`

**杨植麟**：`它在某个地方可能摧毁人类吗？我承认就是说我们得做很多的事情。特别是你现在其实看到很多AI能力，我觉得是有点震惊的。就是因为你根本半年前你都想不到现在能做到这样的程度。需要做很多很多事情。而且同时我认为就是可能人的独特价值在这个过程中，它还是会持续存在。就人的体验、人的情感这些东西它是没有办法被AI去替代。`

**杨植麟**：`人有可能会有很多创造性的工作是AI去做。但是我觉得后两条就是说可能它还是会是以人为中心。但如果它创造拿走了的话，它其实把生产力拿走了，这无所谓。因为人是可以享受这个生产的结果。就是如果我们有一个好的机制的话。它需要改变社会的机制，对。但也是一个缓慢的过程，它不会是说你一两年做完，它可能是要一二十年逐渐的去调整。`

## 术语表

| 术语 | 解释 |
|------|------|
| K2 | 月之暗面基于MoE架构的开源编程和Agentic智能体大模型 |
| Agentic LLM | 能够与外界交互、边思考边执行多轮操作的智能体模型 |
| 缸中之脑 | 杨植麟比喻，指不需要与外界交互、仅在"大脑"内思考就能解题的AI（如O1类推理模型） |
| Test-time Scaling | 在推理/测试阶段通过增加计算量（更多token或更多轮次）提升模型能力 |
| Token Efficiency | 代币效率——用更少的token完成更多任务的指标 |
| RL (强化学习) | 通过奖励信号让模型自主探索最优策略 |
| SFT (监督微调) | 通过标注数据直接教会模型"应该这样做" |
| Reward Hacking | 奖励被钻空子——模型找到取悦评估指标但未真正达成目标的方式 |
| PTX Loss | 预训练与微调混合损失函数，SFT作为先验防止模型"飞太远" |
| Agent | 能动性AI——不仅思考，还能与环境交互执行任务的AI |
| MoE | Mixture of Experts，专家混合模型架构 |
