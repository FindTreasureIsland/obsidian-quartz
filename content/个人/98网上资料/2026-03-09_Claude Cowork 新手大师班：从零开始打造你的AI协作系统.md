第一章：理解Cowork——它不是聊天机器人

1.1 三种Claude，三种角色

很多人把Claude的三个产品搞混，导致用错了工具。

是对话。你问一句，它答一句，你全程在场。

是开发。它在终端里写代码，执行命令，你得懂技术才能指挥。

是委托。你描述"完成是什么样子"，它自己规划，执行、交付，你可以走开。

Chat 像是打电话问朋友建议

Code 像是雇了一个程序员坐在你旁边

Cowork 像是给员工派了一个任务，明天来收结果

对于大多数非技术背景的人来说，Cowork才是真正的效率杠杆。

1.2 Cowork的核心能力

Cowork是一整套能力的组合，而不仅仅是一个功能：

：直接访问你电脑上的文件夹，读取内容、创建新文件、重命名、移动

：把复杂任务拆成小步骤，一步步完成

：遇到可以同时做的事，会启动多个"子智能体"并行工作

：设置好触发条件，自动执行（比如每周一早上生成周报）

：连接外部服务（Slack、Notion、日历等）

：Cowork不是一次对话，是一次任务委派。

第二章：环境搭建（20分钟）

claude.com/download

下载Claude Desktop

登录你的付费账号（Pro版$20/月足够）

打开应用，点击顶部的「Cowork」标签

不要把整个Documents文件夹授权给Cowork。

为什么？因为Cowork有真实的读写权限。虽然出错概率很低，但万一它误删了你的重要文件，你会很痛苦。

正确做法是创建一个专用文件夹：

~/Claude-Workspace/
├── _context/         # 上下文文件（下划线让它排在最前面）
├── projects/         # 进行中的项目
│   ├── project-a/
│   └── project-b/
├── templates/        # 模板文件
├── outputs/          # Claude交付成果
└── archive/          # 归档（Claude通常不读取）

因为它会让文件夹在列表中排到最前面，Claude扫描时第一个就能看到。

在Cowork界面中：

点击「Add Folder」

选择你刚创建的 Claude-Workspace 文件夹

现在Claude可以读写这个文件夹里的所有内容了。

第三章：上下文架构——让Claude"认识你"

3.1 为什么上下文文件如此关键

没有上下文文件时，每次对话都是"新朋友"：

Claude不知道你是谁

输出永远是"通用AI味"

有了上下文文件，每次对话都是"老同事"：

知道你的身份和优先事项

输出一出来就是你要的样子

：花30分钟写好这三个文件，之后每次任务都能省10分钟调整。一周下来省几个小时。

3.2 三个核心上下文文件

在 _context/ 文件夹中创建三个文件：

文件一：about-me.md（你是谁）

这不是简历。是让Claude快速理解"你日常在做什么"的文件。

# 关于我

## 基本信息
- 姓名：[你的名字]
- 角色：[你的职位/身份]
- 公司/领域：[你所在的行业]

## 当前工作重心
1. [最近在推进的项目1]
2. [最近在推进的项目2]
3. [最近在推进的项目3]

## 我服务的对象
- [你的客户/读者/用户是谁]
- [他们关心什么]

## 我的专业领域
- [领域1]
- [领域2]

## 我不擅长的事
- [你希望Claude帮你补足的短板]

文件二：voice-style.md（你的风格）

这个文件决定Claude输出的"味道"是不是你的。

# 我的写作风格

## 整体调性
[描述你的风格，比如：简洁直接，专业但不枯燥、有观点但不偏激]

## 我喜欢的表达方式
- [例如：短句为主，节奏感强]
- [例如：喜欢用具体数字和案例]
- [例如：适当使用反问句]

## 我绝对不用的表达
- [例如：首先/其次/最后这种教科书结构]
- [例如："值得一提的是"、"综上所述"这类套话]
- [例如：过多emoji]

## 格式偏好
- [例如：中文用中文标点，数字用阿拉伯数字]
- [例如：标题不超过15个字]
- [例如：段落不超过4行]

## 写作样本
以下是我写过的内容，体现了我的风格：

### 样本1：[标题]
[粘贴一段你写得满意的内容，200-300字]

### 样本2：[标题]
[再粘贴一段，最好是不同类型的内容]

因为描述风格很抽象，但真实的写作样本能让Claude直接"模仿"你的节奏和用词习惯。

文件三：working-rules.md（工作规则）

这个文件告诉Claude"怎么和你协作"。

# 工作规则

## 启动任务前
- 如果任务描述不清晰，先问我澄清问题，不要猜测
- 在开始执行前，先给我看一个简要计划（不超过5步）
- 等我确认后再动手

## 执行任务时
- 遇到不确定的地方，标记出来让我决定，不要自作主张
- 如果任务太大，建议我拆分成多个小任务
- 保持进度可见：完成一个阶段就告诉我

## 交付成果时
- 默认输出格式：[.docx / .md / 其他]
- 文件命名规则：YYYY-MM-DD-描述性名称
- 交付到：/outputs/ 文件夹

## 绝对禁止
- 未经我确认，不删除任何文件
- 不输出空洞的客套话
- 不在没有依据的情况下编造数据

## 质量标准
- 每个输出都应该是可以直接使用的，不需要我再大幅修改
- 如果你对某个部分信心不足，明确告诉我

3.3 如何让Claude每次都读取这些文件

方式一：全局指令（推荐）

设置路径：Settings → Cowork → Edit Global Instructions

每次开始任务前，先读取 _context/ 文件夹中的三个文件：
1. about-me.md - 了解我是谁
2. voice-style.md - 了解我的风格
3. working-rules.md - 了解工作规则

按照这些文件中的要求执行任务。如有冲突，当前任务的具体要求优先。

方式二：在项目文件夹放一个 _MANIFEST.md

当你有多个项目，每个项目有不同的上下文要求时，可以在项目文件夹里放一个清单文件：

# 项目：客户A季度报告

## 必读文件（Tier 1）
- /_context/about-me.md
- /_context/voice-style.md
- /projects/client-a/brief.md

## 按需读取（Tier 2）
- /projects/client-a/data/ - 数据文件
- /projects/client-a/references/ - 参考资料

## 不要读取（Tier 3）
- /projects/client-a/archive/ - 旧版本，仅归档

第四章：你的第一个Cowork任务

4.1 任务设计的三要素

一个好的Cowork任务描述，需要回答三个问题：

"帮我整理一下这个文件夹"

"把 /projects/receipts/ 文件夹里的所有文件整理一下：按类型分成子文件夹：发票、合同、收据、其他
重命名为 YYYY-MM-DD-描述 格式
生成一个 changes-log.md 记录所有操作
如果文件归属不明确，放到 /needs-review/ 文件夹
不要删除任何文件"

4.2 实操练习：整理混乱文件夹

：你有一个积攒了几个月的下载文件夹，里面什么都有。

在 projects/ 下创建 cleanup-test/ 文件夹

把一些测试文件放进去（建议先用副本测试）

打开Cowork，输入：

整理 /projects/cleanup-test/ 文件夹：

## 目标
把杂乱的文件按类型分类，并统一命名规范。

## 分类规则
- 图片（jpg, png, gif, webp）→ /images/
- 文档（pdf, docx, doc, txt, md）→ /documents/
- 表格（xlsx, csv）→ /spreadsheets/
- 其他 → /misc/

## 命名规则
- 格式：YYYY-MM-DD-原文件名（保留原名便于追溯）
- 日期取文件的修改时间

## 交付物
1. 整理后的文件夹结构
2. 一个 cleanup-log.md 文件，记录每个文件的原位置和新位置

## 约束
- 不删除任何文件
- 无法判断的文件放入 /needs-review/

Claude会先给你看计划，确认后再执行

有一个日志文件记录了所有变更

4.3 实操练习：从原始素材生成报告

：你有会议录音的文字稿、一些研究链接、几页笔记，需要生成一份正式报告。

在 projects/ 下创建 report-test/ 文件夹

基于 /projects/report-test/ 文件夹中的素材，生成一份客户报告。

## 输入素材
- meeting-notes.md - 会议记录
- research-links.txt - 相关资料链接
- my-thoughts.md - 我的初步想法

## 报告结构
1. 执行摘要（200字以内，给忙碌的人看）
2. 背景与目标
3. 关键发现（3-5条）
4. 建议方案
5. 下一步行动

## 风格要求
参考我的 /_context/voice-style.md

## 输出
- 文件名：YYYY-MM-DD-client-report.docx
- 保存到：/outputs/

第五章：定时任务——让工作自动运行

5.1 定时任务的价值

有些工作每周、每天都要做，而且步骤固定。比如：

每周一早上整理上周的工作记录

这些工作非常适合自动化。

5.2 如何设置定时任务

在任务描述中使用 /schedule 命令：

/schedule

每周一早上9点执行以下任务：

1. 读取 /projects/weekly-review/ 文件夹中所有本周创建的文件
2. 汇总成一份周报，包括：
   - 本周完成的事项
   - 遇到的问题
   - 下周计划
3. 保存到 /outputs/weekly-reports/YYYY-MM-DD-weekly.md

Claude会引导你完成设置。

定时任务需要电脑开着、Claude Desktop运行中

如果任务时间到了但电脑在休眠，会在醒来后补执行

5.3 定时任务案例：每日竞品监控

/schedule

每天早上8点执行：

## 任务
监控以下竞品的最新动态：
- [竞品A网站]
- [竞品B网站]  
- [竞品C网站]

## 关注内容
- 产品更新
- 定价变化
- 新功能发布
- 重要公告

## 输出
- 只有发现新内容时才生成报告
- 文件名：YYYY-MM-DD-competitor-update.md
- 保存到：/outputs/daily-intel/

6.3 创建可复用的技能文件

如果你有一个经常执行的复杂任务，可以写成一个"技能文件"：

文件：_context/skills/article-draft.md

# 技能：文章草稿生成

## 用途
从主题和大纲生成2000字左右的文章草稿

## 输入
- 主题
- 目标读者
- 大纲（3-5个要点）
- 参考资料（可选）

## 处理流程
1. 如有参考资料，先阅读并提取关键信息
2. 基于大纲构建文章框架
3. 每个要点展开300-500字
4. 开头要有吸引力，结尾要有行动召唤
5. 按 /_context/voice-style.md 调整风格

## 输出
- 格式：Markdown
- 包含：标题、正文、配图建议
- 标记需要我确认或补充的地方

## 质量检查
- 没有空洞的套话
- 至少3个具体案例或数据
- 每段不超过4行

读者：对AI感兴趣的职场人
大纲：
1. 现状：大多数人还在手工处理重复性工作
2. 变化：AI工具的三个层次
3. 方法：如何选择适合自己的AI工具

第七章：常见问题与注意事项

：只给Cowork访问专用工作文件夹

：密码、财务数据、个人隐私文件不要放在Cowork可访问的范围

首次运行新任务时要监督

：看Claude的执行计划，确认无误再批准

：虽然出错概率低，但养成备份习惯有备无患

Q：Claude读错了文件怎么办？

A：使用 _MANIFEST.md 明确告诉Claude哪些文件要读、哪些不要读。

Q：输出质量不稳定怎么办？

A：90%的情况是上下文文件没写好。优化你的 voice-style.md 和 working-rules.md。

Q：任务太复杂，Claude卡住了怎么办？

A：把大任务拆成小任务。每个任务专注做一件事。

Q：定时任务没执行怎么办？

A：检查电脑是否在休眠。Cowork只在电脑唤醒且App运行时才能执行定时任务。

：5个相关任务合成1个任务，比分5次提交效率高

：_context/ 文件夹里只放必要的文件，太多会拖慢速度

：已完成的部分不要全部重做，用"修改第X部分"代替"全部重写"

完成这个教程后，按这个顺序行动：

[ ] 下载安装Claude Desktop

[ ] 创建 Claude-Workspace 文件夹结构

[ ] 写完三个核心上下文文件

[ ] 完成"整理文件夹"练习

[ ] 完成"生成报告"练习

[ ] 设置一个定时任务（哪怕是简单的每日提醒）

[ ] 建立2-3个常用技能文件

[ ] 连接一个外部工具（Slack或Notion）

[ ] 根据使用经验优化你的上下文文件

结语：系统思维 vs 技巧思维

ChatGPT时代，我们追求"更聪明的提示词"。

Cowork时代，我们要追求"更好的系统"。

提示词是一次性的——每次都要重新写。 系统是可复用的——搭建一次，持续受益。

那些用Cowork效果不好的人，往往是在用ChatGPT的思维方式：每次都写一大段提示词，结果总是不稳定。

那些用Cowork效果很好的人，都花时间在搭建系统：上下文文件、文件夹结构、技能模板、全局指令。一旦搭好，用10个字的指令就能得到满意的结果。

投入2小时搭建系统，每天都能赚回来。

这就是Cowork的正确打开方式。
