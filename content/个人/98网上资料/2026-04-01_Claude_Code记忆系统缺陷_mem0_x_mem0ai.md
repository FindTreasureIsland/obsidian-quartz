## 事件背景

Claude Code 的源码泄露后，工程师们蜂拥去研究提示词、工具定义、计费逻辑。mem0 团队直奔最关键的地方：`src/memdir/`——Claude Code 的记忆系统目录。

结果发现了一个致命缺陷：200行上限，默默删除你的Agent记忆。

## Claude Code 记忆系统架构

### 基本原理

Claude Code 把记忆存储为本地磁盘上的普通 Markdown 文件：

```
路径：~/.claude/projects/<项目名>/memory/
```

每个项目有独立文件夹，每次对话结束后文件会保留。这就是整个持久化模型。

### 索引文件 MEMORY.md

每个记忆文件夹根目录有一个 `MEMORY.md` 索引文件。Claude Code 每次启动时都会读取这个索引，了解有哪些记忆可用。

**问题就出在这里。**

## 致命缺陷：200行上限

MEMORY.md 有两个硬性限制：

1. **200行最大限制** — 如果索引超过200行，系统会默默截断它
2. **25KB最大限制** — 独立字节限制，用于处理超长行

**最可怕的是：失败是静默的。**

你刚写到第201行，最早的记忆就从索引底部掉下去了。Claude 下次启动时完全不知道这些记忆存在。它不会报错、不会提示、只是忘记。

代码注释里写了一个警告，但那个警告只有你主动去翻文件才能看到。Claude 看到的是干净的系统提示词，完全不知道索引被截断了。

## 四种记忆类型

Claude Code 的记忆被严格限定为四种类型：

| 类型 | 内容 |
|------|------|
| User（用户记忆） | 你是谁、角色、专业领域、沟通偏好。只对你自己可见。 |
| Feedback（反馈记忆） | 你给过的指导、纠正、验证过的方法、需要停止做的事。 |
| Project（项目记忆） | 代码库里正在发生什么。死线、决策、不能从代码推导出来的架构背景。 |
| Reference（参考记忆） | 指向外部系统的指针。比如Bug tracker在哪、关注哪个Slack频道。 |

代码里明确写道：**如果一个信息能从当前代码库里通过 grep 或 git 推导出来，就不应该存为记忆。**

## Sonnet 辅助调用

每个对话轮次，Claude Code 都会向 Claude Sonnet 发起一个独立的 API 调用——只是为了找出哪些记忆文件和当前查询相关。

流程：
1. 扫描所有记忆文件
2. 提取文件名和描述清单
3. 发送给 Sonnet
4. 让它选出最相关的最多5个文件

**这不是向量搜索，不是 Embedding。** 只是一个语言模型在读文件名列表然后做判断。

## 记忆新鲜度警告

源码里有个 `memoryFreshnessText()` 函数，为超过1天的记忆生成"过时"警告：

> "这个记忆是X天前的。记忆是时间点观察，不是实时状态。关于代码行为的声明或文件引用可能已过时。"

这个警告会被直接加到记忆内容里。但只有被加载的记忆才会触发警告——被截断的记忆从来没被加载过，所以不会有任何警告。Claude 无法知道自己不知道什么。

## 背景提取Agent

对话结束后有一个 `extract-memories` agent 在后台运行。它会回顾对话中发生的事，自动提取记忆。

这意味着有两样东西在同时往你的记忆目录写入：主Agent在对话中实时写入，后台提取器在对话结束后整理。

代码里有 feature flags 控制这个功能（`EXTRACT_MEMORIES`, `tengu_passport_quail`）。不是所有人都能用，但架构已经在了。

## 团队记忆

还有一个 `TEAMMEM` feature flag 用于团队级记忆。

启用后，部分记忆是私有的（只有你可见），部分记忆是团队共享的（所有贡献者都能看到）。项目约定放进团队记忆，个人偏好留在私有记忆。

## Claude 真正遗忘的场景

想象一下：

你用 Claude Code 在一个真实项目上工作了三个月。它已经学会了：
- 你的偏好和工作方式
- 1月份做出的架构决策
- 那个端点不稳定，测试时不应该依赖它
- 你们团队对热修复跳过PR审查

然后你写到了第201行。

索引被默默截断。最早的记忆从底部掉下去了。下次 Claude 启动时，它带着全新的上下文，完全不知道这些记忆存在过。

接下来发生的事：
- Claude 写了一个测试，碰了那个不稳定的端点
- Claude 又问你关于PR审查政策的事
- Claude 推翻了你几个月前同意的架构

**这不是幻觉。不是bug。只是——忘了。而且没办法告诉你。**

## mem0：修复方案

Claude Code 默认系统是精心设计的 v1——扁平的 Markdown 文件、清晰的四类分类、考虑周全的新鲜度警告。对大多数项目来说是正确的起点。

但它有上限：200行索引、每轮5个文件、没有 Embedding。

mem0 完全替换了这一层：用向量存储代替 Markdown 文件、用 Embedding 相似度代替 Sonnet 读文件名。没有索引截断、没有记忆悬崖、没有静默丢失。半年前的记忆如果和当前工作相关，就能浮出水面。

### mem0 插件安装

两条命令安装：

```
/plugin marketplace add mem0ai/mem0
/plugin install mem0@mem0-plugins
```

安装后获得：语义搜索、跨会话召回、完整记忆管理（add_memory、search_memories、update_memory、delete_memory）。

### mem0 的核心差异

mem0 是专为生产级 AI Agent 构建的记忆层：

| 对比项 | Claude Code 默认 | mem0 |
|--------|------------------|------|
| 存储方式 | 扁平 Markdown 文件 | 向量存储 |
| 检索方式 | Sonnet 读文件名 | Embedding 语义相似度 |
| 索引上限 | 200行 | 无 |
| 文件上限 | 每轮5个 | 无 |
| 截断风险 | 有，静默丢失 | 无 |
