## 背景：Loro 是什么

Loro 是一个高性能的 **CRDTs 框架**，解决多端同步和多人协作上的数据冲突问题。

- 例如笔记场景、设计软件场景，同时编辑一份文档，可能离线、可能并行
- CRDTs 是分布式场景、离线优先场景下解决数据冲突自动合并的算法
- 不保证强一致性，但保证最终一致性
- 相较于 OT 中心化算法，CRDTs 可以做到业务无关、自带版本控制、端到端加密
- **理念**：本地优先，用户自己设备上的那份数据才是 truth of source

---

## 为什么做 Lody

需要一个自己的场景来反馈：
- 有多端同步需求的
- 和 AI 相关的
- 能带来现金流的
- 必须每天自己在用的 dogfood

所以做了 **Lody**：在所有平台（桌面端、Web端、移动端）来控制你自己的设备上的任意 Code Agent。

## Lody 当前版本的功能

### 左侧 Sidebar
三种对话类型：
- **Chat**：普通对话
- **Local Project**：本地项目
- **GitHub WorkTree**：自动管理 worktree 进行并行开发，有 PR、分支自动关联等

### 中间对话区
- 友好 GUI 展示对话内容和 Agent 执行过程
- 每轮对话后可看到 Agent 修改结果
- 可以发送图像给 Agent，Agent 也可以返回图像

### 右侧信息区
- 查看文件
- 查看当前对话文件变更
- 查看对应 PR 信息

### 移动端
- 桌面端简单改了一下适合移动端布局
- 所有能力和桌面端一致

## Lody 解决了什么问题

### Code Agent 的痛点
- 任务跑十几分钟到半小时，复杂任务可能一个多小时
- 不能干等着，开新窗口可能互相干扰
- Claude Code 经常遇到一个偷偷把另一个改的还原了

### 解决方案
**worktree 只给 agent 用，Lody 做好创建和回收：**
- 人类用本地自己的工作目录
- 想开发哪个切哪个，env 同一份
- 测试前 git pull 一下
- 有问题继续之前的对话，让 AI 继续修

**最大好处**：节省注意力。完全不用考虑单工作区多窗口是否功能模块正交，不用考虑功能在哪个目录，worktree 怎么管理。

### 多端同步的好处
- 不用担心被打断，出门、坐地铁、遛狗，完全没有心理负担
- 拿起手机就走，打开后和电脑前完全一样的状态
- 支持多人协作、离线优先、端到端加密
- **最爽体验**：高铁上发指令，到了没信号的地方，执行在服务器上，等有信号，一切都完成了

### 控制端和执行端分离的好处
- 除了信用卡因素，很难触发 Claude 封号
- 可以共享订阅、稳定 IP

### ACP 对接所有 Code CLI
- 可以在一处同时使用和管理所有模型
- 不同模型有不同侧重点，点一下 tab 选另一个模型继续工作
- 对话会分散在各个应用或 CLI 里

### 对话即源代码
- Coding 对话才是真的源代码，是可以交互的源代码
- 团队中互相问某个功能怎么做的、怎么修复的，直接发一个 Lody 链接

## Lody 之后要解决的问题

### 团队中如何更加 AI Native 开发软件

不仅仅包括 coding，而是完整流程：
- 立项、PRD编写、技术调研、市场调研、设计稿、开发实现

**Lody 会成为 AI Native 软件开发团队的 workspace。**

Coding Agent 就是通用 Agent，Lody 的角色是**团队的 Context 同步层**。

### 现在开发团队的问题

代码在 Git 里，但真正的上下文散落在各处：
- Notion 文档
- Figma 设计
- Slack 讨论
- Linear issue
- PR review comments
- 和 AI 对话的内容

### Context 问题的表现
- 新人接手某个模块，经常需要花大量时间重建上下文
- 三个月后回看自己写的代码
- AI 由于缺少足够上下文进入局部最优，错误理解之前代码

### Lody 的解决方向
把这些对话、决策过程、迭代历史都**结构化地保存下来**，并且和代码关联起来，变成可以被检索、被复用、被继承的知识。

开新对话时，AI 要修改相关代码，会自动关联到已有的历史对话。

**依托 Loro CRDTs 作为底层数据层：**
- 所有 context 数据有版本控制
- 离线优先
- 以最开放的格式（如文件）本地优先保存
- 相当于提供了面向 context 结构化数据的 git

## Multi-Agent 的构想

### 异构模型 vs 同构模型

亚马逊论文《Rethinking the Value of Multi-Agent Workflow》：
- 同质模型进行角色分工来完成任务，本质和单个模型串行依次完成任务差别不大
- 反而吃不到 cache 让成本更高

**Lody 是中立平台，可以使用各类模型，异构 multi-agent：**
- Claude 擅长 UI
- Codex 擅长逻辑代码
- 小任务给国内便宜模型

### Multi-Agent 的必要性

Codex 负责人 tibo 表示：未来一年内任务完成时间会缩短一个数量级。

如果是真的：
- 现在基础任务跑半小时，缩短十倍变成五六分钟
- 当前所有交互模式都不再适用
- 发出去几个任务挨个收菜的方式会过时

**把能自动化验证的环节都交给 agent 是必然的。**

构想：
- 通过 Lody agent 表达意图
- 它理解意图、分析任务方向和难度、分配给擅长对应子 agent
- 子 agent 互相交流，便宜模型向最强模型请求帮助
- 完整周期自动化走完

## 总结

**Lody 和所有做 AI Agent 的目标大差不差：**

拥有 context 的前提下，你就拥有了最懂你们团队的 **Agent Leader**。

这个 Leader：
- 知道你工作区的全部事情：哪些功能在开发、哪些 bug 在修复、哪些任务卡住了
- 可以创建新对话，把任务分配给专门的 coding agent
- 需要 review 时叫 review agent，需要搜索时派 search agent
- 理解每个 agent 的能力边界
- 理解你的工作习惯和优先级

**差异：在 Context 上**

- 本地优先方式管理所有数据
- 所有 context 在多个设备之间、团队成员之间无缝同步
- 端到端加密、自带版本管理、不会产生冲突
- 最开放地管理所有 context，不担心数据丢失、泄露、供应商锁定

**愿景**：让每个人都能随时随地指挥自己的 Agent 团队，享受 AI 带来的效率提升，同时不失对数据的控制权和安全感。
