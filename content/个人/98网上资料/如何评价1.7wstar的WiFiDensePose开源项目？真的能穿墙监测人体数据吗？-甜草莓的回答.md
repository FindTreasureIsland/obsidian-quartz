最近，我的朋友圈和 GitHub 动态几乎被一个名为 WiFi DeepPose的项目刷屏了。很多不明就里的朋友发来私信问我：“你们研究了这么多年的通感一体和WiFi 感知，是不是被这个开源项目给降维打击了？甚至有投资人来咨询，这种通过 WiFi 信号就能实时还原人体三维姿态的技术，是不是已经到了商用爆发的前夜？

面对这些提问，作为一名在无线感知领域深耕多年的研究者，我的回答多少带点无奈：**它是骗局，也不是骗局。**

说它不是骗局，是因为它确实描绘了一个在无线通信领域追寻了十几年的终极愿景。我们总是希望利用环境中的无线信号，像视觉一样实现高精度的被动式感知。这个逻辑在物理学上是自洽的，在学术界也早有大量的论文支撑[^1]。

但说它是骗局，是因为当我去仔细看它的Github仓库后，突然意识到它完美避开了目前无线感知领域所有真正棘手的、足以让顶尖研究者掉头发的问题，假设这些问题应该被用户自己解决。

![[a4f28aafd2994ad0025b371c5f007914.png|图示：WiFi 感知实现实时还原人体三维姿态]]

-   它宣称的开箱即用也并不能实现，因为目前几乎没有 Intel 5300 网卡的产品在售。
-   它也没有内置训练权重，也并未使用（而只是提供了几个）开放数据集。
-   目前的演示数据全是随机数据，毫无意义。

换句话说，它缺乏真正的学术和工程价值。 为了让大家理解为这个项目，我们需要先聊聊，WiFi 感知到底是怎么一回事，以及目前我们真正走到了哪一步。

## 一、WiFi 感知为什么能成立？

在评估 WiFi DeepPose 之前，必须明确无线感知的物理边界。WiFi 感知的核心在于对**信道状态信息**的相干处理。

根据 IEEE 802.11 协议标准，WiFi 采用 **正交频分复用（OFDM）** 技术。以 20MHz 带宽为例，信号分布在 52 个数据子载波上（而在 40MHz 或 80MHz 下，子载波数量分别增加至 114 或 242 个）。接收端解码出的 CSI 实际上是一个复数矩阵 ，表征了特定子载波在时间步的基带信道响应。

![[e855156dc3e99d0018554f289daaded0.png|图示：不同活动中一个子载波 CSI 幅度的频谱图：（a）站立，（b）坐下，（c）躺下，（d）跌倒，（e）行走，（f）跑步。]]

当人体（作为一个具有特定介电常数的散射体）在空间中移动时，会改变多径分布。学术界已经证明，通过提取**多普勒频率变化** 和 **到达角**，可以高精度还原人体骨架和人体行为[^2][^3]。

这里有一些极其复杂的非线性映射关系，需要通过严谨的信号处理和深度学习来解耦。比如，接收端解码出的 CSI 实际上是一个复数矩阵，表征了特定子载波在时间步的基带信道响应。当人体在空间中移动时，会改变多径分布。学术界已经证明，通过提取多普勒频移和到达角，理论上确实可以高精度还原人体骨架和行为。

![[705778e84f49f9d2289b069bfcdfd771.png|图示：一项名为CSI-Channel Spatial Decomposition Strategy (CSDS)的研究在公开数据集Wi-Pose上的预测结果。结果表明，基于CSI数据预测的人体骨骼与实际情况吻合良好。]]

但这仅仅是“理论上”。物理原理是真实的，信号中确实携带着人体运动的信息。**但要从嘈杂的信号里把信息"提纯"出来，是一条布满荆棘的技术之路。**

这也是为什么，当我仔细审视这个 WiFi-DensePose项目时，感受到了一种强烈的魔幻现实主义。

## 二、DeepPose，这很不 WiFi

我仔细翻看了这个项目所有者的 GitHub 提交记录和代码结构，第一反应是：这绝对是写 AI Agent 或搞大模型调优的高手，但大概率不是无线通信领域的专业人员。他在上层建筑上花的心思，远超对底层物理信号的敬畏。 这个项目完美诠释了什么是 AI 时代的氛围编程。

![[0f0de9884e7ecb80f44df314aed8fe5b.png|图示：利用大语言模型搭建工程工作流]]

作者利用大语言模型极其高效地拉起了一个堪称完美的工程工作流。如果你平时也搞搞云原生、写写 Kubernetes 的部署脚本或 Operator，你会觉得这套外壳极其亲切且专业：Docker 镜像齐备，REST API 规范，服务编排无懈可击，Markdown 文档排版精美。它给人一种来嘛，上手就能用的错觉。但当你顺着漂亮的接口往里挖，试图寻找那个能把无线特征转化为 3D 骨架的核心算法时，你会发现内部逻辑是断裂的。

-   **那么维护者到底是谁？**从 GitHub 提交记录和代码结构来看，项目所有者更像是一名擅长 Agent 开发或大模型调优的工程师，而非无线通信领域的专业人员。

![[3a3e323cc5b82fb47992dd553cd77d50.png|图示：wifi-densepose的GitHub代码仓]]

最让人啼笑皆非的是，项目在最该硬核的地方，使用了随机数据（Mock Data）来替代真实的 CSI 信号输入。诚然，从软件工程的角度流程确实跑通了，各种PASS指标看起来很诱人。但这种绕过复杂的物理环境、直接在模拟出的完美数据上跑出来的系统，在学术研究和工程落地中都没有任何参考价值。这就像建了一座从外观上看美轮美奂的桥，但用来造桥的材料是纸板，因为没人真的敢开车上去。

当社区在Issue中提出质疑时，项目方打开了Issue #37，回复："No, this is not fake. Yes, it actually works. Read the docs"。这是一种典型的防御性回应，而不是用技术证明自己。另一个质疑假星的Issue #12，被直接删除了。

## 三、房间里的大象被项目完美避开

这个项目之所以大概率是空中楼阁，是因为它完美避开了目前WiFi感知领域真正棘手的三大难题。

### 1、无线数据标注

WiFi Sensing领域，获取精准的Ground Truth是极高成本的。

![[954befcd441df450d4be1a8685f75c0b.png|图示：利用惯性磁单元和红外摄像机组成的无线传感器网络来进行动作捕捉]]

比如要做姿态估计，通常需要同步采集WiFi信号和光学动捕（MoCap）数据，需要构建昂贵的同步采集系统。让实验者在六路摄像头的拍摄下，同步WiFi 设备与视频设备，这是微秒级时间同步和逐帧对齐。通常，我们采集一个小时的干净数据需要几天时间来清洗标注。

DeepPose 项目根本没有说明，也不可能说明它的海量高质量数据从何而来，因为AI编程不会把重点放在这些地方。

### 2、硬件泛化性

WiFi Sensing目前实现面临的另一个难题：硬件和环境的泛化性[^4]。

![[76506121d920c78493b5a068dba4e8e2.png|图示：硬件多样性及环境的多样性]]

假如我们在会议室 A，用一套 Intel 5300 网卡或特定的家用路由器，训练出了一个精度高达 95% 的行为识别模型；一旦你把设备挪到卧室 B，或者哪怕只是换了一张桌子的位置，由于多径效应的彻底改变，模型的性能就会面临断崖式下跌。

为什么？因为CSI数据里混杂着环境反射、硬件失真、噪声干扰。要根据多径信号还原姿态，算法必须极其精确地知道每个发射天线和接收天线的绝对物理空间位置。深度学习模型很容易记住这些环境特征，而不是真正学会提取人体运动的信号。这个项目的架构里，完全没有考虑跨环境、跨硬件的鲁棒性问题。 当然，这是因为它没有在真实数据上试验过。

### 3、信号预处理

市面上普通的 WiFi 路由器，其硬件振荡器是极其廉价的，这会导致严重的载波频率偏移和采样频率偏移。

![[77d5c2e1bef22675ae0b95465dda52d6.png|图示：理想16QAM星座图，点阵清晰，落在标准位置。存在CFO/SFO时，点阵旋转成环状，或呈“星云状”散开]]

这会导致直接抓下来的 CSI 相位数据，在图表上看起来像是一团无规律的随机噪声。相位偏移怎么校正？采样频率偏移怎么补偿？突发噪声怎么滤除？这些脏活，占了真实系统80%的工程量。

WiFi DeepPose中，这部分信号处理实现了Hampel 滤波、SpotFi 相位校正、Fresnel 模型，但是并没有测试真实效能。

## 四、我们在做什么？无线感知的脚踏实地

那么问题来了：如果WiFi DensePose是空中楼阁，那真正想做这件事的人，应该把脚踩在哪里？

### 1、SDP Challenge的诞生：一场全球竞赛

2025年11月，在 MobiCom 2025 上，我们举办了第一届 SDP Sensing Challenge (SSC 2025)。这场赛事，吸引了来自全球学术界和工业界的 **305个团队、773名选手**参与。参赛团队围绕无线感知技术与AI深度融合的关键挑战，提交了大量创新方案。

![[aaa7ecef8c47c1a434f96fb4c9df59fc.jpg|图示：赛事留影]]

联合主办方包括IEEE通信感知一体化新兴技术委员会、中国通信企业协会，以及华为、英特尔、中兴、丰田、LG电子等产业巨头。大会联合主席：IEEE 802.11工作组前主席Dorothy Stanley、中国工程院外籍院士罗智泉、华为无线CTO童文、Intel无线CTO Carlos Cordeiro。而IEEE 802.11bf（WLAN感知标准）的主席Tony Xiao Han，亲自担任执行主席。

为什么要拉上这么多产业界的大牛？因为我们坚信：WiFi感知的落地，必须是学术界和产业界联手攻坚的事，而不是一个人在GitHub上自嗨的样板间。

### 2、数据孤岛到统一基准：SDP数据集[^5]

过去几年，WiFi感知领域最大的痛点是“数据孤岛”——每家实验室用自己的设备、自己的环境、自己的协议采数据，论文里的指标没法复现，更没法对比。我们看到了太多脱离物理实际的 Demo，也看到了学术界各个团队因为使用了不同的硬件、不同的环境，导致论文指标无法横向对比的窘境，这种论文指标对产业落地毫无意义。

![[b7d013c779e5eed1615fe3c4b1aae119.png|图示：针对"数据孤岛"而开源SDP数据集]]

为此，我们做了一个关键动作：开源SDP数据集（SDP官网：[SSC2025 Competition - Software Defined Network Contest](https://link.zhihu.com/?target=http%3A//www.sdp8.org/)）。我们一次性放出了覆盖 7大典型感知应用场景的大规模实测数据，总时长超过 400小时，可供研究人员进行各种感知任务的算法研究和模型训练。同时开源了一个开箱即用的预训练流程（[SDP协议Github](https://link.zhihu.com/?target=https%3A//github.com/yuanhao-cui/Sensing-Data-Protocol)）。这些场景包括：

-   存在检测：人体、宠物等目标的感知
-   定位与跟踪：人员、车辆、无人机等的轨迹跟踪
-   动作识别：手势识别、人体动作识别
-   生命体征监测：呼吸、心跳、睡眠监测
-   成像：人体骨骼重建、环境重构

这些数据全部来自**真实环境、真实硬件、真实场景**，而不是实验室里精心调校的“示范数据”。我们提供了多种设备（不同型号的WiFi网卡、毫米波雷达、5G基站等）、多个环境（家庭、办公室、会议室、户外）、多个人体目标，确保数据的多样性和挑战性。

![[2eebb401a4601ecb98b9da1b48223753.png|图示：开源SDP数据集]]

更重要的是，SDP平台不仅开源了数据集，还提供了一套**统一的预处理基准**，让大家能够在真实的物理信号上进行算法竞争，而不是在 Mock Data 上自嗨。你的模型强不强，在统一的基准下测一测就知道。

只有站在同一个起跑线上，技术的进步才是真实的、可积累的。把地基打牢，再去建上面的3D骨架高楼。

### 3、邀请真正想解决问题的人

如果你真的对WiFi感知感兴趣，而不是追热点，而是想解决真实问题——我们邀请你尝试SDP数据集和标准化流程。这是通往真正商用的唯一路径：基于真实物理层数据，严谨预处理，并在统一的基准上迭代算法。而不是在一个炫酷的README后面，藏着np.random.rand()。

![[adb82d1e08755a205c530735abee69bb.png|图示：SDP 统一预处理基准。第一阶段消除硬件带来的缺陷，例如 STO 和 CFO；第二阶段将不同的 CSI 投影到统一的规范张量；第三阶段将张量展平为标记序列，以便 Transformer 主干网使用。]]

## 五、总结-从愿景回归物理世界

WiFi DensePose的火爆，说明了大众对智能感知的渴望。这种渴望是真实的，也是合理的。在养老监护、跌倒检测、入侵预警这些场景里，WiFi感知确实有不可替代的价值。

**但越是狂热，越需要清醒。**

1.7万颗Star的GitHub，当朋友圈被炫酷的穿墙火柴人刷屏，我们必须停下来问一句：这背后，是真实可落地的技术突破，还是精心包装的演示逻辑？

物理世界的信号是嘈杂的，环境是变化的，硬件是不完美的。这是每一个真正做过无线感知的人都绕不开的现实。WiFi感知要想真正落地，没有捷径可走，必须基于真实的物理层数据，必须做扎实的信号预处理，必须在跨环境、跨硬件的测试中反复迭代。

仰望星空描绘愿景固然让人心潮澎湃，但路，终究要一步一个脚印地走。
