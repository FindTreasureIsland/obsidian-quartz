## 一、OpenClaw 内置浏览器架构——比你想的复杂

### 1. 端口层级：一个数字推导出整个系统

OpenClaw 的所有服务端口从一个基数推导：gateway.port（默认 18789）。

| 服务 | 端口 |
|------|------|
| Bridge | 18790 |
| Control Service | 18791 |
| CDP Relay | 18792 |
| Canvas | 18793 |
| 托管浏览器 CDP | 18800-18899 |

Control Service 只绑定 loopback——刻意的安全设计。

**优点**：确定性——知道 gateway 端口就能推算出所有其他端口

**缺点**：CLI 硬编码 18791，自定义端口时整个系统崩溃

### 2. 三种控制模式

**模式一：OpenClaw 托管浏览器**

独立的 Chromium 实例，拥有自己的用户数据目录。OpenClaw 管理全生命周期。每个 profile 分配一个专用 CDP 端口（从 18800 起）。

适用场景：需要干净环境的自动化任务。

**模式二：Chrome 扩展 Relay**

最有趣也最脆弱的模式。Chrome 扩展把用户现有的 Chrome 标签页——连同真实的 cookies、session、登录态——桥接给 Gateway。

MV3 扩展，background.js 作为 service worker，通过 chrome.debugger API 附着到活动标签页，CDP 命令经 WebSocket 双向转发。

这个模式的价值是真实性，但也是问题最多的模式。

**模式三：远程 CDP**

直接指定一个 CDP URL，连接到远程运行的 Chromium。用于分布式部署：Docker 容器，云端沙箱。

### 3. 快照系统：OpenClaw 浏览器的核心创新

这是最聪明的设计决策。

**传统方案**：截图——把整个网页渲染成图片，喂给视觉模型分析。问题是：截图的 base64 编码可以轻松达到数 MB 级别，一次浏览器操作就能撑爆上下文窗口。

**OpenClaw 的答案：语义快照（Semantic Snapshot）**

快照系统把网页转换成结构化文本，比如 `button "Sign In" [ref=e1]`。Agent 先运行快照识别交互元素，再用引用编号发出动作指令。

快照有多种格式，核心两种：

- **AI 模式（默认）**：调用 Playwright 内部快照 API，生成 e1/e12 风格引用。默认最大 80,000 字符
- **ARIA 模式**：原始可访问性树，生成 ax1/ax2 风格引用

### 4. Chrome 扩展 Relay：系统中最薄弱的环节

社区在整理 GitHub Issues 时，一个模式非常清晰：扩展 relay 是浏览器子系统中 bug 最密集的区域。

问题可以归为四类：

1. **WebSocket 断连与状态丢失**：页面导航后断连、频繁断连、切换标签页后连接丢失
2. **MV3 Service Worker 生命周期**：Chrome 在空闲 ~30 秒后杀死 service worker。如果 relay 断开或 worker 重启，扩展会"忘记"已附着的标签页
3. **协议握手缺陷**：缺少 connect.challenge 处理器、/extension 端点返回 404、Token 不匹配
4. **macOS 特有问题**：SSRF 检查阻断 loopback CDP、Profile 路由 bug

**韭二哥评**：
- 语义快照 > 截图。数量级的 token 成本差距不是微调能弥合的
- 三模式覆盖：托管浏览器、扩展 relay、远程 CDP——覆盖几乎所有使用场景
- 硬伤：扩展 relay 的工程质量。MV3 service worker 的生命周期管理、WebSocket 断连恢复、多标签页状态同步——社区 fork 已经证明了解决方案存在，但官方尚未合并

## 二、技术路线——四条路，两个赢家

AI 控制浏览器，本质上有四种方式：

### 路线一：纯视觉（截图 + LLM）

Agent 截图，喂给视觉模型，模型输出点击坐标和键盘操作。

代表：Claude Computer Use、OpenAI Operator

| 优点 | 缺点 |
|------|------|
| 最通用 | 慢、贵、不够精确 |

### 路线二：纯 DOM / 可访问性树

提取页面的可访问性树，压缩后喂给 LLM。

代表：Playwright MCP

| 优点 | 缺点 |
|------|------|
| 快、确定性、token 成本低 | Shadow DOM 是致命盲点 |

### 路线三：Hybrid（可访问性树 + 选择性视觉）——正在赢

可访问性树作为主要上下文，对不可访问的元素补充截图。

代表：Stagehand、Browser-Use

| 优点 |
|------|
| 兼得两家之长 |

### 路线四：自然语言到动作

用户说"帮我订机票"，Agent 直接执行。

代表：MultiOn、Skyvern

| 缺点 |
|------|
| 最不可预测 |

**结论**：Hybrid 路线已经赢了。这不是预测，是既成事实——资金最多的公司（BrowserBase $67.5M）、stars 最多的开源项目（Browser-Use 79K）、以及最大的云厂商（Google Chrome Auto Browse）都在走这条路。

## 三、核心玩家深度拆解

### 1. Browser-Use：社区之王

Python 库，把任何 LLM 变成完全自主的浏览器自动化 Agent。

创始团队：Magnus Muller 和 Gregor Zunic，ETH Zurich 数据科学研究生。4 天做出 demo，发到 Hacker News，3 个月 50K stars。

**核心数据**：
- ~79,000+ GitHub Stars
- $17M 种子轮（Felicis 领投，Paul Graham 参投）
- YC W25

**自研模型**：
- BU-1.0 (74.7%) → BU-2.0 (83.3%，匹配 Claude Opus 4.5 但快 40%) → BU-30B-A3B-Preview (MoE 架构，200 任务/$1)

**但基准数据有争议**：自报 WebVoyager 89.1%，独立复现只有 60.2% LLM 验证成功率（高估 20-50%）

### 2. BrowserBase + Stagehand：资本之王

**BrowserBase（基础设施层）**：云浏览器平台，声称自己是"AWS for headless browsers"。

- 估值 $300M（2025.6 B 轮）
- 总融资 $67.5M
- 1,000+ 付费组织
- 2025 年处理 5000 万浏览器会话
- 天使投资人：Patrick Collison（Stripe）、Guillermo Rauch（Vercel）

**Stagehand（SDK 层）**：AI 驱动的浏览器自动化框架。~20,000+ stars。

核心洞察：给开发者三个原子 AI 原语——act(instruction)、extract(instruction, schema)、observe(instruction)。

v3 移除 Playwright 依赖，直接通过 CDP 通信，44% 速度提升。

**关系**：Stagehand 是开源飞轮，BrowserBase 是付费基础设施。

### 3. Skyvern：视觉流派的代表

多 Agent 架构 + 计算机视觉做浏览器工作流自动化。

- 20,300+ stars
- $2.7M 种子轮
- $0.05/步

Planner-Actor-Validator 三 Agent 循环。纯视觉路线——不解析 DOM，对布局变化天然免疫。

WebVoyager 85.85%（表单填写最强）。

### 4. 其他玩家简述

| 项目 | 特点 |
|------|------|
| **Magnitude** | 纯视觉浏览器 Agent，WebVoyager 93.9%（开源 SOTA） |
| **MultiOn** | $20M 融资，$100M 估值，闭源 API + Chrome 扩展。最大问题：没有 MCP server |
| **AgentQL** | Web 页面的 SQL——用自然语言描述你要什么数据。有官方 MCP server |
| **Vercel agent-browser** | Rust + Node.js 混合架构，声称比 Playwright MCP 节省 82-93% 上下文空间 |

### 5. Pinchtab：Go 编写的独立 HTTP 服务器

把浏览器自动化暴露为 REST API。~1,900+ stars，12MB 单二进制，零依赖。

可访问性树 + 稳定元素引用（e0, e1, e2...）。

**Token 效率**：
- /text 模式：~800 tokens
- 交互式快照：~3,600 tokens

内置隐身模式和会话持久化。填补了一个真实空白——不是所有 Agent 都跑在 Python/TypeScript 里，curl 就能调用。

## 四、GUI Agent——与浏览器 Agent 的范式对决

**定义**：不解析 DOM，不依赖可访问性树，纯视觉驱动，截图 → VLM 推理 → 坐标点击/键盘输入，覆盖任意有视觉界面的系统。

### 两种范式，一个战场

Browser Agent 的优势来自结构化信息（DOM/a11y tree），GUI Agent 的优势来自通用性（任何有像素的界面都能操作）。

两者不是同一条路线的前后版本，而是正交的范式选择。

### 1. UI-TARS（字节跳动）：迭代最快的 GUI Agent

- 27.8K GitHub stars，Apache-2.0 开源
- 2025.1 发布到 UI-TARS-2（2025.9），迭代速度极快

**基准表现**：
- OSWorld 47.5%
- AndroidWorld 73.3%
- Online-Mind2Web 88.2%
- ScreenSpot-V2 94.2%

**产品化**：闭源版本集成进中兴努比亚 M153 成为"豆包手机"系统级 Agent。定价 3,499 元，24 小时内售罄 30,000 台。2026 年被称为"AI Agent 手机量产元年"。

### 2. Open-AutoGLM（智谱 AI）：中文移动生态的最强选手

- 23.9K GitHub stars，MIT 开源
- 中文移动 App 任务：89.7%（远超同类）

针对中国超级 App（微信、支付宝、美团、抖音）的嵌套界面和小程序做了大量优化。

### 3. MAI-UI（阿里巴巴通义）：移动端当前 SOTA

MoE 235B-A22B（基于 Qwen3-VL）。AndroidWorld 76.7%（#1）。

**韭二哥评论**：根据 DigiRL（Berkeley），SFT 17.7% → 离线 RL 32.4% → 在线 RL（DigiRL）67.2%。接近 4 倍提升。

这意味着：**强化学习（而非模型规模或数据量）才是解锁 GUI Agent 能力的关键杠杆**。

### 4. Anthropic 收购 Vercept——视觉感知人才争夺战

2026 年 2 月 25 日，Anthropic 收购 Vercept。四位联合创始人中三位加入 Anthropic：Ross Girshick（SAM/R-CNN）、Kiana Ehsani（具身 AI）、Luca Weihs（Agent 训练基础设施）。第四位 Matt Deitke 被 Meta 以 $250M/4 年合约挖走。

这笔收购说明 Anthropic 认为视觉感知是计算机操控的关键瓶颈，Claude Computer Use 的演化方向是从 Browser Agent 向 GUI Agent 靠拢。

## 六、MCP 浏览器生态——标准化接口的胜利

### MCP 采纳时间线

- 2024.11：Anthropic 发布 MCP
- 2025.3：OpenAI 采纳 MCP；Microsoft 发布 Playwright MCP
- 2025.4：Google 确认 Gemini 支持 MCP
- 2025.12：MCP 捐赠给 Linux Foundation
- 2026 初：全行业广泛采纳，435+ 浏览器相关 MCP server
- 2026.2：WebMCP 草案（W3C)，Chrome 146 Canary 实验性预览

**结论**：MCP 已经是"USB 接口"了。不是在变成，是已经变成了。

### Playwright MCP：事实标准

确立了可访问性树作为 AI-浏览器交互的正确抽象。不发送截图，不发送原始 HTML。发送语义化的、只包含交互元素的结构化表示。

**已知限制**：Shadow DOM。现代设计系统把元素藏在 shadow root 里，可访问性树看不到。这是 2026 年的头号架构弱点。

| 方案 | 完成率 | 成本 |
|------|--------|------|
| Stagehand + Claude Sonnet 4.6 | ~75% | 中等 |

## 十、安全——Agent 上网的阿喀琉斯之踵

Agent 浏览器自动化的安全问题不是边缘情况，是结构性缺陷。

### 核心发现

1. **攻击面巨大且独特**：Meta FAIR 的 WASP 基准测试发现，即使是顶级模型，面对低成本提示注入攻击，部分攻击成功率高达 86%

2. **安全对齐在 Agent 化后退化**：同一个 LLM 作为聊天机器人会拒绝有害指令，但作为浏览器 Agent 会尝试执行。GPT-4o Agent 尝试了 100 个有害行为中的 98 个

3. **没有 Agent 在安全评测上表现良好**：评测 16 个主流 LLM Agent，没有一个安全分数超过 60%

4. **隐私是盲区**：Agent 倾向于不必要地使用敏感信息，处理登录凭证和 API 密钥时存在高风险故障点

5. **暗黑模式是 Agent 的新型攻击面**：面对单个暗黑模式，Agent 平均 41% 的时间会被欺骗

### 新兴防御方案

| 方案 | 特点 |
|------|------|
| **ceLLMate** | Agent 级最小权限策略 |
| **AgentBound** | 首个 MCP server 访问控制框架 |
| **WebSentinel** | 两步检测+定位，准确率 0.991 |
| **Anthropic 多层防御** | Claude Opus 4.5 成功注入率降至 1% |
| **AgentSpec** | DSL 指定运行时安全约束 |

## 十一、现状分析小结

1. **Hybrid 架构已经赢了**：资金最多的公司、Stars 最多的项目、最大的云厂商——都在走 Hybrid

2. **MCP 标准化是既成事实**：OpenAI、Google、Microsoft、Amazon 全部采纳。435+ 浏览器 MCP server。任何不支持 MCP 的工具正在自我边缘化

3. **基准测试在系统性地高估真实能力**：WebVoyager ~90% → Online-Mind2Web 61%。20-30pp 的落差是结构性的

4. **Shadow DOM 是 2026 年可访问性树方案的最大技术挑战**：React、Angular、Web Components 都大量使用 Shadow DOM，Playwright MCP 看不到 shadow root 内的元素

5. **Browser-Use 的自研模型路线是值得关注的技术方向**：BU-30B-A3B-Preview：200 任务/$1，浏览器专用 LLM 的成本效率已远超通用模型

6. **GUI Agent 是正交于 Browser Agent 的第五条路径**：DigiRL 的 RL unlock 证明强化学习是 GUI Agent 能力的关键杠杆。两个范式最终大概率走向 Hybrid 融合
