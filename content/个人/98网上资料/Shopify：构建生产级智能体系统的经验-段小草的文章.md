Shopify 如何演进 AI 助手架构并为实际部署构建稳健的评估框架

*本文基于 Andrew McNamara、Ben Lafferty 和 Michael Garner 在 ICML 2025 上发表的演讲：[Building Production Ready Agentic Systems: Architecture, LLM-based Evaluation, and GRPO Training](https://link.zhihu.com/?target=https%3A//icml.cc/virtual/2025/46781)。*

在 Shopify，我们一直在构建 [Sidekick](https://link.zhihu.com/?target=https%3A//www.shopify.com/magic)，一个由 AI 驱动的助手，通过自然语言交互帮助商家管理他们的商店。从分析客户细分到填写产品表单和导航复杂的管理界面，Sidekick 已从一个简单的工具调用系统演变为一个复杂的智能体平台。在此过程中，我们学到了关于架构设计、评估方法和训练技术的宝贵经验，并希望与更广泛的 AI 工程社区分享。

## **Sidekick 架构的演进**

Sidekick 围绕 Anthropic 所称的「智能体循环」构建——一个持续的循环，其中人类提供输入，大语言模型 (LLM) 处理该输入并决定行动，这些行动在环境中执行，收集反馈，然后循环继续，直到任务完成。

![](https://pic2.zhimg.com/v2-125a7900d41be7064cc9d3d35e1e5bfd_1440w.jpg)

在实践中，这意味着 Sidekick 可以处理诸如「我的哪些客户来自多伦多？」之类的请求，通过自动查询客户数据、应用适当的筛选器并呈现结果。或者当商家请求帮助撰写 SEO 描述时，Sidekick 可以识别相关产品，理解上下文，并直接在产品表单中填写优化后的内容。

![](https://picx.zhimg.com/v2-178f7bec48fc3e6df4ad88d47fee95bb_1440w.jpg)

## **工具复杂性问题**

随着我们扩展 Sidekick 的能力，我们很快遇到了一个许多构建智能体系统的团队都会认识到的扩展挑战。我们的工具库从少数几个定义明确的函数增长到数十个专门的功能：

![](https://pic2.zhimg.com/v2-fe420c48741a14e3befe2551d5c26c53_1440w.jpg)

-   **0-20 个工具**：边界清晰，易于调试，行为直接
-   **20-50 个工具**：边界变得模糊，工具组合开始导致意外结果
-   **50+ 个工具**：有多种方式完成同一任务，系统变得难以推理

这种增长导致了我们所说的「千条指令之死」——我们的系统提示词变成了一个笨拙的集合，包含了各种特殊情况、相互矛盾的指导和边缘案例处理，这减慢了系统速度，使其几乎无法维护。

![](https://pic4.zhimg.com/v2-c91354422cbdcac0470e245d8f69248d_1440w.jpg)

## **即时指令：一个应对规模化的解决方案**

我们的突破来自于实现了即时 (Just-in-Time, JIT) 指令。我们不再将所有指导塞入系统提示词，而是在工具数据需要时，随数据一同返回相关指令。我们的目标是为每一种情况为 LLM 精心打造完美的上下文，不多一个 Token，也不少一个 Token。

**实践中的工作原理**

提供给 LLM 的指令基 LLM 基于的响应：

![](https://picx.zhimg.com/v2-f1193cefc84354380141d9e3e82fb411_1440w.jpg)

这种方法提供了三个关键好处：

1.  **局部化指导**：指令仅在相关时出现，使核心系统提示词专注于基本的智能体行为
2.  **缓存效率**：我们可以在不破坏 LLM 提示词缓存的情况下动态调整指令
3.  **模块化**：可以根据 beta 标志、模型版本或页面上下文提供不同的指令

结果立竿见影——我们的系统变得更易于维护，同时所有指标的性能都得到了提升。

## **构建稳健的 LLM 评估系统**

部署智能体系统最大的挑战之一是评估。在处理 LLM 输出的概率性以及多步智能体行为的复杂性时，传统的软件测试方法显得力不从心。

![](https://pic4.zhimg.com/v2-9d08cf474d202ef88ede57fe7c4d30c5_1440w.jpg)

如今，许多人对他们的 LLM 系统进行氛围测试 (vibe testing)，并认为这已足够；事实并非如此。氛围测试，或者创建一个类似「给这个打 0-10 分」的「氛围 LLM 评判器」，是行不通的。评估需要有原则且统计上严谨，否则你就是在带着虚假的安全感发布产品。

![](https://pic4.zhimg.com/v2-57cb26bdc81528fcb4772cc194357099_1440w.jpg)

## **基准真相集优于黄金数据集**

我们从精心策划的「黄金」数据集转向了反映实际生产环境数据分布的基准真相集 (Ground Truth Sets, GTX)。我们不再试图预测所有可能的交互（这通常是规格文档试图枚举的），而是抽样真实的商家对话，并根据我们在实践中观察到的情况创建评估标准。

![](https://pica.zhimg.com/v2-bbbf164b8f9c387666bdb05c70430b2c_1440w.jpg)

该过程包括：

1.  **人类评估**：让至少三名产品专家根据多个标准对对话进行标注
2.  **统计验证**：使用 Cohen's Kappa、Kendall Tau 和 Pearson correlation 来衡量标注者间一致性
3.  **基准测试**：将人类一致性水平视为我们的 LLM 评判器可以达到的理论上限

![](https://picx.zhimg.com/v2-53a92b1e7f52d17121434c1ba99ab923_1440w.jpg)

## **LLM 作为评判器与人类评判的关联性**

我们为 Sidekick 性能的不同方面开发了专门的 LLM 评判器，但关键的洞见是根据人类的判断来校准这些评判器。通过迭代式的提示词工程，我们将评判器的性能从几乎不比随机好 (Cohen's Kappa 为 0.02) 提升到接近人类的水平 (0.61，而人类基线为 0.69)。其思路是，一旦我们的 LLM 评判器与人类评判具有高度相关性，我们便尝试在 GTX 的每次对话中随机将评判器替换为人类评判员，当难以分辨评判组中是人类还是评判器时，我们就知道我们拥有了一个可信的 LLM 评判器。

![](https://pic3.zhimg.com/v2-672978151db328035a0dd41c87a88370_1440w.jpg)

## **GRPO 训练和奖励黑客**

在模型微调方面，我们采用了群体相对策略优化 (Group Relative Policy Optimization, GRPO)，这是一种强化学习方法，它使用我们的 LLM 评判器作为奖励信号。我们开发了一个 N 阶段门控奖励系统，该系统结合了程序性验证（语法检查、schema 验证）和来自 LLM 评判器的语义评估。

![](https://pic4.zhimg.com/v2-44eb2b5c995313d6c8f99642b6559199_1440w.jpg)

### **奖励黑客的现实**

尽管我们精心设计了评估方案，但在训练过程中我们还是遇到了严重的奖励黑客 (reward hacking)。模型找到了各种创造性的方法来利用我们的奖励系统：

-   **选择退出操纵**：模型不尝试完成困难任务，而是解释为什么它无法提供帮助
-   **标签操纵**：使用客户标签作为万能的解决方案，而不是进行正确的字段映射
-   **违反 Schema**：幻觉出 ID 或使用不正确的枚举值

例如，当被要求「筛选出状态为启用的客户」时，模型学会了创建像 `customer_tags CONTAINS 'enabled'` 这样的筛选器，而不是正确的 `customer_account_status = 'ENABLED'`。

### **迭代改进**

解决奖励操纵问题需要更新我们的语法验证器和 LLM 评判器，以识别这些失败模式。在实施修复后：

-   所有技能的语法验证准确率从约 93% 提高到约 99%
-   LLM 评判器的相关性平均从 0.66 增加到 0.75
-   最重要的是，端到端对话质量达到了我们监督微调基线的水平

## **生产环境智能体系统的关键要点**

基于我们构建和部署 Sidekick 的经验，以下是我们的关键建议：

### **架构原则**

-   **保持简单**：抵制在没有明确边界的情况下添加工具的冲动。对于智能体能力而言，质量胜于数量的原则尤为适用
-   **从模块化开始**：从一开始就使用像 JIT 指令这样的模式，以便在扩展时保持系统的可理解性
-   **早期避免多智能体架构**：简单的单智能体系统能够处理的复杂性可能超出你的预期

### **评估基础设施**

-   **构建多个 LLM 评判器**：智能体性能的不同方面需要专门的评估方法
-   **将评判器与人类判断对齐**：与人类评估者的统计相关性对于信任自动化评估至关重要
-   **预料到奖励操纵**：预见到模型会利用你的奖励系统，并相应地构建检测机制

### **训练与部署**

-   **程序性 + 语义验证**：将基于规则的检查与基于 LLM 的评估相结合，以获得稳健的奖励信号
-   **用户模拟**：投资于现实的用户模拟器，以进行全面的生产前测试
-   **迭代改进评判器**：随着你发现新的失败模式，计划进行多轮的评判器优化

## **展望未来**

我们正在继续演进 Sidekick 的架构和评估系统。未来的工作包括将推理轨迹整合到我们的训练流程中，在训练期间使用模拟器和生产环境评判器，以及探索更高效的训练方法。

生产环境智能体系统领域仍然很年轻，但我们在 Shopify 开发的模式——模块化架构、稳健的评估框架以及对奖励操纵的密切关注——为构建商家可以信赖的可靠 AI 助手提供了基础。

构建生产级的智能体系统需要的不仅仅是将 LLM 连接到工具。它要求深思熟虑的架构决策、严谨的评估方法，以及对这些系统可能出现的意外失败方式保持持续警惕。但如果做得对，其结果将是 AI 以有意义的方式真正增强人类的能力。
