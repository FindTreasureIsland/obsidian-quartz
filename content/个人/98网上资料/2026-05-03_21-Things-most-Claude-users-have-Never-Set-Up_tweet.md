# 21 Things most claude users have Never Set Up and It's Costing them Hours Every Week

**来源**：https://x.com/i/status/2050225292585607440

**作者**：Anatoli Kopadze

**发布时间**：2026-05-03

---

## 核心观点

一个简单的 CLAUDE.md 文件在 GitHub Trending 上登顶第一，获得82,000 stars 和 7,800 forks。

大多数人使用 Claude 但从未听说过这个文件。知道的人也不清楚具体应该写什么。

每次打开新的 Claude 对话，它都从零开始。不知道你的名字、工作、偏好或你喜欢的方式。你要花前几分钟重新解释一切。

**CLAUDE.md 永久解决这个问题。**

---

## 为什么这不只是开发者工具

- **写作者**：用它锁定自己的声音和语调，Claude 永远不会像别人
- **营销人员**：定义受众，Claude 停止写千篇一律的文案
- **研究人员**：设定信息结构方式
- **企业主**：给 Claude 完整的公司背景，让每次输出都符合实际

---

## 如何创建文件（2分钟）

1. 打开项目文件夹，新建文件
2. 命名为 `CLAUDE.md`（大写，无空格）
3. 粘贴相关指令
4. 保存。Claude Code 每次在那个文件夹打开会话时自动读取

---

## How Claude Talks to You（沟通方式）

### 1. Kill the filler
消除"Great question!"、"Of course!"、"Certainly!"等废话开场白。每次回答直接切入正题。

### 2. Always show options before acting
重大任务前，先展示2-3种方法让用户选择方向，再执行。

### 3. Be honest when you don't know
Claude 会在不确定时给出自信而详细的错误答案。这个指令让它在回答前标记不确定性。

### 4. Match length to what's actually needed
简单问题简短回答，复杂工作需要深度时详细展开。

---

## How Claude Behaves（行为方式）

### 5. Ask before making big changes
重大改动前先停下来，告诉你要做什么，等你确认后再执行。

### 6. Stay focused on what was asked
只做被要求的事，不要顺手改其他东西。如果发现其他值得注意的，提出来但不要未经要求就改。

### 7. Always tell me what you changed
任务结束时简短总结：什么变了，什么没变，有什么需要关注。

### 8. Never take actions on my behalf without asking
当 AI 工具连接到你的邮箱、日历、社交账号时，不要擅自发送消息、发内容、安排日程。这个指令创造一道硬墙。

---

## Your Context（你的上下文）

### 9. Tell Claude who you are and what you know
一段关于你是谁的描述能校准之后所有的回答。

### 10. Give Claude the context of what you're working on
关于你正在做什么的简短上下文：受众、目标、约束条件。

### 11. Lock in your voice and style
定义你的写作风格，Claude 从初稿就用你的风格。

---

## Memory & Continuity（记忆与连续性）

### 12. Make Claude keep a memory file
Claude 可以在会话之间写文件，文件是持久化的。指令让它维护一个 MEMORY.md 文件，记录每个重要决策。

### 13. End-of-session summary, never lose progress
会话结束前让 Claude 写一份会话摘要到 MEMORY.md。下次打开时读这个文件，从上次停下的地方继续。

### 14. Log what didn't work, stop solving the same problem twice
错误日志打破重复尝试的循环。每次失败的方法都记录下来，包括试了什么、为什么不work、最终什么成功了。

### 15. Give Claude a list of facts that never change
每个项目都有永久的事实：来自过去决策的约束、因为重要原因存在的规则。定义一次，Claude 每次都记得。

---

## For Developers（给开发者）

### 16. Stay in scope, touch nothing you weren't asked about
只做被要求的事。范围控制是区分精准工具和乱射大炮的关键。

### 17. Confirm before anything destructive
删除文件、覆盖函数、丢弃数据库表——这些是"小心"都不够的情况，是完全停止，需要明确许可。

### 18. Hard stops, actions that never happen without explicit permission
部署到生产环境。在实时数据库上运行迁移。向外部服务发送 API 调用。这些是全面停止的情况，需要你在场并明确说 yes。

### 19. Lock your tech stack
定义你的技术栈一次，Claude 停止推荐你不想要的东西。

### 20. Always show exactly what changed
任务完成后，精确展示哪些文件变了、是否完成了任何未完成的事。

### 21. The 4 rules that made Andrej Karpathy's CLAUDE.md go viral

Andrej Karpathy（特斯拉前 AI 总监、OpenAI 创始成员）识别了让 Claude Code 在编码任务中失败的4个特定行为。开发者把它们提炼成4条指令，写到一个 CLAUDE.md 文件里。那个文件在 GitHub Trending 上登顶第一，将编码准确率从 65% 提高到 94%。

## 总结

**CLAUDE.md 不是开发者工具。**

它是任何认真使用 Claude 的人都应该设置在第一次真正会话之前的永久指令文件。

- **1-4条**：修复 Claude 如何沟通
- **5-8条**：阻止它改变未经授权的东西
- **9-11条**：给它上下文，让输出符合你的实际工作
- **12-15条**：给它目前存在的最接近真实记忆的东西
- **16-21条**：给开发者，让 Claude Code 像精准工具而不是不可预测的大炮
