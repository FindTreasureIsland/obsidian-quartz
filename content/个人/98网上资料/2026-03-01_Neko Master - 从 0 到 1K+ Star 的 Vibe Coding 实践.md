# Neko Master: 从 0 到 1K+ Star 的 Vibe Coding 实践

**作者**: 罗磊
**时间**: 2026-03-01
**来源**: [原始链接](https://luolei.org/neko-master-vibe-coding)

---

## 项目简介

春节期间，我花了四个小时，从零开始 Vibe Coding 了一个网络流量分析面板 **Neko Master**，当天就上线了第一版。项目上线一周，GitHub 收获了 1000+ Star，Docker Pull 破了 10K。

**Neko Master** 是一个开源、自部署的网络流量分析面板：

- 多维流量统计（域名 / 节点 / 规则 / 地区等）
- 趋势分析
- 多后端支持（OpenClash / Mihomo / Surge）
- Docker 一键部署
- 移动端适配 + PWA

## 为什么做这个项目？

我是一个 Homelab 用户，家里跑了一堆服务，分流策略比较复杂。

市面上除了 UniFi 之外，其他统计工具的界面确实有些一言难尽。与其在不同工具之间拼凑数据，不如自己做一个更好看的「流量感知」面板。

## 一小时打造 MVP

2 月 5 日下午，我打开 Kimi Code，使用最新的 K2.5 模型，开始 Vibe Coding。没有画原型图，没有写技术方案，就是在脑子里先搭了个大概框架，然后直接跟 AI 对话。一小时不到，MVP 就跑起来了。

这个项目发布不到 24 小时，就收获了 GitHub 400+ Star，Docker Hub 1000+ 次拉取。

## 让 AI 审美在线

这次开发 Neko Master，听到最多的评价就是「好看」。

分享一个有效技巧：

> 不要只用文字描述「给我写个好看的面板」。要给视觉锚点。
> 
> 去 Dribbble / Figma Community 搜「Dashboard」，挑一张看着舒服的截图直接喂给 AI，告诉它「复刻这个设计感」。

**一个确信的感受是：在 AI 时代，代码的门槛在下降，但审美判断依然是决定成品质量的关键因素。**

## AI 工具复盘

| 工具 | 角色 | 体感 |
|------|------|------|
| Kimi K2.5 | 早期主力 | 量大管饱，中文理解好，MVP 阶段 100% 主力 |
| Claude Code (Opus 4.6) | 硬骨头 | 贵，但遇到架构和性能深水区，只有它能啃 |
| CodeX (GPT 5.2/5.3) | 日常输出 | 5 小时循环用量非常扎实 |
| Gemini 3 Pro | 辅助 | 主要用来 Review 和写 Commit Message |

**国产模型在初始化阶段已经足够高效**。但当项目复杂度提升，面对数据库性能调优、架构重构这些深水区问题时，还是得靠 Claude Opus 4.6 和 CodeX 5.3。

## 技术细节

### 1. 硬盘 I/O 优化

早期版本把每条流量记录都直接单条写入 SQLite，在真实家庭网络里会触发严重写放大。用户反馈磁盘写入量吓人，日写入量 200GB。

后面做了三件事：
- 内存缓冲队列 + 批量落盘（30 秒 flush）
- 先聚合再写入（热点统计先在内存合并）
- 写入限流和背压

效果：
```
v1.0.2 -> v1.0.7 -> v1.0.9
200GB   -> 20GB   -> 1.6GB / day
```

**AI 能快速把"能跑"的代码给出来，但 I/O 模型、缓存策略、背压机制这些基本功，必须由人把关。**

### 2. ClickHouse 优化

ClickHouse 引入后，第一版也踩了典型坑：小批次高频写入导致 parts 激增。

优化方向：
- 写入侧：统一批量写入窗口
- 存储侧：按时间分区 + 低基数字典化
- 查询侧：仪表盘高频指标前置到预聚合层

### 3. AI 在深水区的正确用法

深水区里，AI 最有效的用法不是「一次性生成」，而是进入工程化闭环：

**日志与指标 → 假设 → patch → 压测/对比 → 继续迭代**

## 写在最后

Vibe Coding 确实改变了开发方式，过去需要一两周的原型，现在几小时就能跑起来。

但有一个东西 AI 替代不了：**从「能跑」到「好用」的那段距离。**

- 200GB 的写入 bug 是 AI 写的，但发现问题、定位瓶颈、设计缓存策略是人做的
- 界面从「AI 味」到「SaaS 级」，靠的不是更好的 prompt，而是自己对美的判断
- Agent 模式的架构设计，来自对真实部署场景的理解

**Vibe Coding 降低了「从 0 到 1」的门槛，但「从 1 到 100」的路，依然需要经验、审美和对用户需求的理解。**
