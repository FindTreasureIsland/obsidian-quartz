# Function Call：AI Agent 的手和脚

**来源**：https://www.woshipm.com/ai/6395361.html

**作者**：雪白耶耶猫猫（AI产品经理，专注Agent工作流与GEO优化）

## 一、为什么Function Call是刚需

大模型的底层是概率。它做的事情是预测"在这个对话上下文里，下一个词最可能是什么"。

**大模型非常擅长推理，但它天生不擅长处理事实。**

你问它今天是几号，它可能一本正经地给你一个错的日期。你让它帮你查某个用户的订单状态，它要么编一个看起来合理的，要么直接说"我不知道"。它的知识截止在训练数据那一天，它没有眼睛，没有手，没办法伸出去触碰真实世界正在发生的事情。

**光靠大模型本身，很多看起来很简单的业务需求，根本做不了。**
- 查个实时库存？做不了
- 触发一次支付？做不了
- 给用户发条消息？做不了

它需要"手和脚"——需要能伸出去拿数据、能触发真实操作的能力。这就是Function Call存在的原因。

## 二、Function Call的本质

一句话说清楚：**Function Call，就是让大模型来决定——要不要调用某个函数，以及怎么调。**

你提前告诉模型：我这里准备了几个工具，一个能查天气，一个能查订单，一个能帮用户发短信。然后用户说话，模型读懂意图，自己判断：好，这个情况我需要查订单，参数是用户ID，我来调这个函数。

**模型负责"想"，函数负责"做"。**

### description 是最重要的字段

很多人忽略了一个字段：description（工具描述）。

description 才是模型做决策的唯一依据。模型看不见你的代码逻辑，它只能通过你写的这段描述来判断"这个工具是干什么的，什么时候该用它"。

- 你写得模糊 → 模型乱调用，或者该用的时候不用
- 你写得精确、写清楚使用场景和边界 → 模型像老练的执行者，指哪打哪

**这个字段写好了，比花时间调模型参数有效得多。**

### 完整链路

```
用户说话 → 模型理解意图 → 模型决定调哪个函数、传什么参数 → 函数在真实世界执行 → 结果返回给模型 → 模型整合信息，回答用户
```

输入、决策、执行、反馈，缺一不可。

## 三、AI PM实战经验

### 坑1：把任务拆几步完成

复杂任务一步到位容易出问题。我们曾想让AI一步到位：分析数据、生成报告、发邮件，全部自动搞定。结果每次都出问题。

后来拆成三个独立步骤，每步一个任务，单独跑，单独校验。成功率直接翻了一倍多。

**复杂任务串成链，每个节点职责单一，出问题了能定位，成功了也可复用。**

### 坑2：明确System Prompt里的调用场景

你不只是告诉模型"有这些工具"，你还要告诉它"什么时候用、什么时候不用"。

例子：客服Agent有一个查订单的接口。一开始没有写使用条件，结果用户只是随便聊了一句"我最近买了个东西"，模型就去调查询接口了，完全没必要。

后来加了一句：**"当用户明确提出要查询某个具体订单的状态时，才调用此工具，不可根据模糊意图主动触发。"**

加了这句话之后，模型行为稳定了很多。

### 坑3：必须要人机协同，确保安全

这一条是原则问题，不是效率问题。

AI调用工具的准确率再高，也会有出错的时候。如果场景涉及真实的金钱、真实的数据写入、真实的外部操作，就必须设置人工确认的节点。

做过一个自动发货Agent，测试了上百个case全部通过。但真实用户的输入永远比你想象的更野——有个用户把收货地址写成了一句绕口令，Agent差点生成了发货单。

**AI可以帮你想、帮你准备，但涉及不可逆操作，最后那一步确认，必须是人来按。自动化是为了提效，不是为了甩锅。**

## 四、怎么构建你自己的AI Agent

### 第一步：场景图谱化

不要一上来就想"我要做一个万能助手"。先把你的业务场景画出来：用户会来做什么事？高频场景是什么？低频但重要的场景是什么？把这些场景列出来，变成一张图，这是你的起点。

### 第二步：明确输入和输出

每个场景要想清楚：用户的输入长什么样？你期望系统输出的结果是什么？这两头想清楚了，中间需要哪些工具、哪些步骤，就自然出来了。

很多人一上来就去写代码，结果做到一半发现方向不对。**把输入输出想清楚，是最便宜的设计投入。**

### 第三步：准备典型问题，进行模型测试

自己准备一批测试用例——包括正常的case、边界case、刁钻的输入。用这些去测Agent，看它在哪里掉链子，哪里表现超出预期。

这个过程不只是在测模型，也在测你的工具描述写得够不够清晰，System Prompt设计得够不够合理。

## 五、总结

Function Call本质上是函数调用，但它的意义远不止于此。它是**连接大模型推理能力和真实世界执行能力的桥梁**。

没有它，大模型再聪明也只是一个会说话的玩具；有了它，AI才真正长出了手和脚，能干活，能落地，能创造价值。

现在Function Call已经足够成熟了。主流的模型都支持，工具生态也越来越丰富。这意味着对于AI PM来说，核心问题已经不是"技术能不能实现"，而是**"业务场景想不想清楚"**。

把场景想清楚，把工具描述写清楚，把人机协同的边界划清楚，你就可以在这个基础上，搭出真正能用的AI Agent。
