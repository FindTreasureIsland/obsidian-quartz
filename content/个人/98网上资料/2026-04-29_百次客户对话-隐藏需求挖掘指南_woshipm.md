# 百次客户对话提炼：值得收藏的"隐藏需求"挖掘指南

**来源**：https://www.woshipm.com/pd/6386128.html

**作者**：雪碧要提升算力（深耕招采领域产品）

**发布时间**：2026-04-29

---

## 一、先说一个翻车故事

作者第一次做专家管理系统需求调研，客户赵主任说"加个随机抽取功能，选专业、选人数，一键抽出来就行"。

结果第一周电话来了：
- 抽出来的专家有些上个月刚参加过评审
- 有些专家被抽中次数比其他人少得多

客户说的"加个随机抽取"，只是冰山浮在水面上的一个尖角。

**水面之下真正的需求**：
- 抽取要有频次感知
- 抽取结果要可追溯
- 操作员能筛选和查看历史
- 能统计各专家被抽频率

---

## 二、理论的起点：需求的"冰山模型"

McGovern冰山模型：用户表达出来的需求只是冰山一角，水面下90%的需求是看不见的。

```
┌─────────────────────────────┐
│ 客户明确说出的需求           │ ← 水面之上（10%）
├─────────────────────────────┤
│ 客户以为你说能懂的需求       │
├─────────────────────────────┤
│ 客户没想到的系统需求         │
├─────────────────────────────┤
│ 行业法规驱动的隐藏需求       │ ← 水面之下（90%）
├─────────────────────────────┤
│ 组织政治层面的需求           │
└─────────────────────────────┘
```

**招投标业务的特点**：客户的诉求往往隐藏在规则和合规里。不聊合规，听到的都是碎片需求；聊起合规，自动补全一大半。

## 三、四维探查法：系统性挖掘隐藏需求

### 维度一：流程还原法（Task Analysis）

**核心理念**：不要问"你们要什么"，是让用户走一遍"你们现在怎么做"。

**关键观察点**：
- 卡顿点：哪一步犹豫了、切换系统了、翻笔记本了
- 绕路操作：先把数据导出Excel，处理完再导回来
- 心理检查点：每操作几步停下来核对数据
- 人工补偿：系统在脑子里/纸面上完成的逻辑判断

**真实案例**：
操作员在系统里点了"随机抽取"，生成专家列表后，把列表复制到Excel，和上个月参加过的项目进行一一比对——因为系统只按专业和地区抽，同一个专家一个月内反复被抽到"传出去不好听"。

**三类客户的应对策略**：

| 客户类型 | 占比 | 策略 |
|----------|------|------|
| 配合型 | 40% | 少问，多看，当记录员 |
| 防御型 | 35% | 放低姿态，"你教我" |
| 粗糙型 | 25% | 慢放，问"停了一下是在检查什么" |

### 维度二：异常逆推法（FMEA思维）

**核心理念**：问"正常流程怎么走"讲不清楚，问"出错了怎么办"一下就有话说了。

**真实案例**：
问"如果专家抽出来了但临时缺席怎么办"：
- 要先确认能不能等，不行就补抽
- 补抽的专家和已签到入场的不能碰面，得分开安排评标室
- 补抽记录也要单独标注，不然审计说不清楚

**三类客户的异常话题策略**：

| 客户类型 | 策略 |
|----------|------|
| 配合型 | 允许发散，及时收束 |
| 防御型 | 换词——"出错"→"特殊情况"，主语从"你"→"流程" |
| 粗糙型 | 给具体触发点，"如果……会怎样" |

### 维度三：角色切换法（Empathy Map）

**核心理念**：同一个系统，不同角色看到的和需要的完全不同。

**三类角色**：

| 角色 | 关心什么 | 沟通语言 |
|------|----------|----------|
| 管理者（主任/科长） | 目标导向：风险、效率、汇报 | 翻译成"风险和效率" |
| 操作者（办事员） | 过程导向：好不好用、少点几下 | 去工位上聊，问具体操作 |
| 监管者（纪检/审计） | 证据导向：出事了能查到是谁吗 | 聊"审计视角" |

**典型翻车案例**：只跟信息科主任聊，做了"增删改查"。上线后操作员崩溃——每天录30多个专家，单位名称每次手动输入，专业分类200多个选项。

### 维度四：规则推演法（Goal-Directed Design）

**核心理念**：问用户要通过功能达成什么业务目标。在招投标行业，业务目标几乎都落在"合规地完成XX"。

**切入方式**：聊法规比聊业务目标更有效。

**真实案例**：法规要求"专家社保缴纳单位纳入回避单位范围"——客户思考后意识到"历史工作单位怎么处理？需不需要专家履历管理？"

**三类客户的切入方式**：

| 客户类型 | 切入方式 |
|----------|----------|
| 配合型（懂行） | 直接聊法规条文，当同行 |
| 防御型 | 聊"同行怎么做"，不讲规则 |
| 粗糙型 | 拉近——"如果现在不改，到时候会怎样" |

## 四、漏斗式提问法

从开放到封闭，逐层收紧：

```
┌─────────────────┐
│ 开放式提问      │ "你们现在怎么做"
└────────┬────────┘
         ↓
┌─────────────────┐
│ 探查式提问      │ "遇到XX怎么处理"
└────────┬────────┘
         ↓
┌─────────────────┐
│ 确认式提问      │ "我的理解对吗"
└────────┬────────┘
         ↓
┌─────────────────┐
│ 引导式提问      │ "如果能自动XX呢"
└─────────────────┘
```

### 两个有效技巧

**技巧一：沉默法**
问完开放式问题后，等3秒钟不要说话。大部分人会在沉默中补充信息。

**技巧二：反向验证法**
在确认式阶段，把你的理解用清晰的话说出来，让客户确认或纠正。

## 五、总结

**需求调研万能公式**：

```
需求调研万能公式 = 冰山模型（认知框架）
                 + 四维探查法（分析方法）
                 + 漏斗问法（沟通话术）
                 + AI辅助（效率工具）
```

**核心洞察**：
- 不要问用户要什么，看他怎么做，比他说的更真实
- 正常的流程用户讲不全，但出过的错他能讲一上午
- 需求沟通不是语言的问题，是角色的问题
- 需求调研不是一门"技术"，而是一门"手艺"。技术可以学，手艺只能练
