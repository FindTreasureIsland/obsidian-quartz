## 主要内容

### 背景：为什么是 Harness

你搭过一个聊天机器人，接入了 ReAct 循环，挂了几个工具，演示效果不错。然后你尝试把它做成生产级产品，问题随之而来：模型记不住三步前做了什么，工具调用静默失败，上下文窗口被垃圾填满。

**问题不在模型。在模型周围的一切。**

LangChain 用一个案例证明了这一点：只改了包裹 LLM 的基础设施，模型权重完全没动，在 TerminalBench 2.0 上的排名从 30 名开外直接跳到第 5。另一个研究项目让 LLM 自己优化基础设施，通过率达到 76.4%，超过了人工设计的系统。

### 什么是 Agent Harness

Harness 是包裹 LLM 的完整软件基础设施：编排循环、工具、记忆、上下文管理、状态持久化、错误处理、安全护栏。

Anthropic 在 Claude Code 文档里直接写明：SDK 就是「驱动 Claude Code 的 agent harness」。OpenAI 的 Codex 团队也用同样的框架，把「agent」和「harness」视为等价概念。

**核心区分**：「agent」是涌现出来的行为，是用户交互的那个有目标、会用工具、能自我纠正的实体。Harness 是产生这种行为的机器。

Beren Millidge 的精准类比：裸 LLM 是没有内存、没有硬盘、没有 I/O 的 CPU。上下文窗口是内存，快但有限；外部数据库是硬盘，大但慢；工具集成是设备驱动；Harness 是操作系统。

### 三个工程层级

围绕模型有三个同心圆层级：
- **提示词工程**：负责设计模型接收的指令
- **上下文工程**：管理模型看到什么、什么时候看到
- **Harness 工程**：包含前两者，再加上完整的应用基础设施

### 生产级 Harness 的 12 个组件

#### 1. 编排循环
这是心跳所在。它实现思考-行动-观察（TAO）循环，也叫 ReAct 循环：组装提示词、调用 LLM、解析输出、执行工具调用、把结果反馈回去、重复直到完成。

#### 2. 工具
工具是 agent 的手。它们以 schema 形式定义（名称、描述、参数类型），注入到 LLM 的上下文中。Claude Code 提供六个类别的工具：文件操作、搜索、执行、网络访问、代码智能、以及子 agent 生成。

#### 3. 记忆
记忆在多个时间尺度上运作：
- **短期记忆**：单次会话内的对话历史
- **长期记忆**：跨会话持久化（Claude Code 使用 CLAUDE.md 和 MEMORY.md；LangGraph 使用命名空间组织的 JSON Store）

Claude Code 实现了三层层级：轻量级索引、按需拉取的详细主题文件、以及只通过搜索访问的原始记录。

#### 4. 上下文管理
这是很多 agent 悄然失败的地方。核心问题是**上下文腐烂**：当关键内容落在窗口中间位置时，模型性能下降超过 30%。

生产级策略包括：
- **压缩**：对对话历史进行摘要（Claude Code 在压缩时保留架构决策和未解决的 bug，丢弃冗余的工具输出）
- **观察屏蔽**：隐藏旧的工具输出，但保留工具调用可见
- **即时检索**：维护轻量级标识符，动态加载数据
- **子 agent 委托**：每个子 agent 只返回 1000-2000 token 的压缩摘要

#### 5. 提示词构建
组装模型在每一步实际看到的内容，是分层的：系统提示、工具定义、记忆文件、对话历史、当前用户消息。

OpenAI 的 Codex 使用严格的优先级栈：服务器控制的系统消息（最高优先级）、工具定义、开发者指令、用户指令（级联的 AGENTS.md 文件，32 KiB 上限），然后是对话历史。

#### 6. 输出解析
解析 LLM 的输出，提取结构化数据（如工具调用参数）。常见方法包括：正则表达式、JSON 解析、结构化输出（OpenAI 的 `response_format`）等。

#### 7. 状态管理
跨请求跟踪任务进度和中间结果。Vivek Trivedy（LangChain）指出：大多数 agent 实现中最大的问题是缺乏结构化的任务状态管理——agent 需要知道完成到哪一步了。

#### 8. 错误处理
涵盖 LLM 错误（速率限制、无效响应）、工具错误（工具不存在、参数错误、网络超时）和编排循环错误。

#### 9. 护栏与安全
包括输入验证、输出过滤、权限控制、审计日志。Anthropic 明确把护栏作为 harness 的独立组件。

#### 10. 验证循环
在 agent 执行关键操作前进行验证（如文件删除确认、敏感操作二次确认），防止灾难性错误。

#### 11. 子 Agent 编排
复杂任务分解给专门的子 agent 处理。Claude Code 支持递归生成子 agent，每个子 agent 有自己的上下文、工具集和任务范围。

#### 12. 持久化层
Harness 状态的保存与恢复，支持 agent 在中断后继续工作。Claude Code 使用文件系统（CLAUDE.md、MEMORY.md、.claude/history/）、VibeDev 使用 SQLite、OpenAI Agents SDK 支持 Redis。

### 框架对比

| 框架 | 编排模型 | 工具 | 记忆 | 持久化 |
|------|---------|------|------|--------|
| Anthropic Claude Code | 递归 + 人类协作 | Schema 注册 | 三层记忆系统 | 文件系统 |
| OpenAI Agents SDK | 函数优先 | @function_tool + MCP | Session (SQLite/Redis) | 有状态 |
| LangGraph | 状态图 | 预构建 + 自定义 | 命名空间 Store | Checkpointing |
| CrewAI | 角色 + 协作 | 函数工具 | 会话历史 | 有状态 |
| AutoGen | 多智能体协作 | 函数工具 | 消息历史 | 有状态 |

### Harness 的七个关键决策

1. **循环机制**：基于 LLM 的判断 vs 预定义控制流
2. **记忆策略**：轻量级索引 vs 详细记忆 vs 即时检索
3. **工具边界**：支持哪些工具、如何定义、如何执行
4. **状态粒度**：结构化任务跟踪 vs 简单历史回溯
5. **上下文策略**：上下文压缩 vs 滑动窗口 vs 即时检索
6. **容错机制**：重试策略、回退方案、降级模式
7. **持久化方案**：文件系统 vs 数据库 vs 混合方案

### 结论

模型能力越来越强，但是 Harness 不会消失。Harness 是将无状态的 LLM 转变为有能力的 Agent 的关键。随着模型能力的提升，Harness 的质量将成为产品竞争力的核心差异。
