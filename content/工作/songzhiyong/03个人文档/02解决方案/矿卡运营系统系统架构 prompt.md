# 矿卡综合运营管理系统 — 系统架构 Prompt

> 基于《矿卡综合运营管理平台-产品规划V1.0》第四章节（业务流程）与第六章节（系统架构）提炼，用于指导系统架构设计与技术选型。

---

## 一、系统定位

设计一套 **AI Agent 驱动的新能源矿卡综合运营管理系统**，以「人类决策 + Agent 执行」协作模式，覆盖车辆从采购到报废的全生命周期，打通「车-桩-货-人-钱」五大要素。

**核心目标**：一个运营大脑 + 五个 AI Agent，让 500 台矿卡像一台一样被管理。

---

## 二、五层系统架构

```
┌──────────────────────────────────────────────────────────────┐
│  ⑤ 智能体层（AI Agents）                                       │
│  调度Agent │ 安全Agent │ 结算Agent │ 资产Agent │ 数据Agent        │
├──────────────────────────────────────────────────────────────┤
│  ④ 数据服务层                                                 │
│  车辆数据服务 │ 运单数据服务 │ 结算数据服务 │ 能耗数据服务 │ 资产数据服务   │
├──────────────────────────────────────────────────────────────┤
│  ③ 业务流程层                                                 │
│  🚛 管车：持车→出库→资产管理→资产安全→租售运营→归档                 │
│  📦 管物流：运输执行 → 结算                                     │
├──────────────────────────────────────────────────────────────┤
│  ② 数据底座                                                  │
│  IoT数据采集 │ 磅单AI识别 │ 数据清洗 │ 统一API │ 数据存储           │
├──────────────────────────────────────────────────────────────┤
│  ① 业务系统层（现有外部系统）                                     │
│  → 智驭维科车辆平台（单向采集）│ ↔ 自建充电桩平台（双向）              │
│  ← 飞书（单向推送）│ → 上下游Excel/表单（单向采集）                  │
└──────────────────────────────────────────────────────────────┘
```

### 层间关系

- **L1 → L2**：智驭维科/Excel表单通过 API/OCR 单向采集进入数据底座；充电桩平台源码级双向同步；飞书单向推送通知
- **L2 → L3**：清洗后的结构化数据驱动管车与管物流两大业务流程
- **L3 → L4**：业务流程产生数据服务能力（车辆/运单/结算/能耗/资产）
- **L4 → L5**：数据服务为 AI Agent 提供推理与决策所需上下文

## 三、两大业务域

### 🚛 管车 — 车辆资产全生命周期

覆盖 6 大业务模块：

| 模块 | 核心流程 | 涉及角色 |
|------|---------|---------|
| 车辆持车 | 订车→购买→交付→上牌→整备→入库 | 采购(总经办)、财务、车务岗、车务数据岗 |
| 车辆出库 | 自营出库（需求发起→审核→预检→合同→交接→出库）/ 租赁出库（需求对接→报价→风控→合同→交付） | 物流运营部、车务岗、车队长、销售岗、法务、财务 |
| 车辆资产管理 | 保险购买（预警→询价→审核→付款→归档）/ 索赔管理 / 年检年审 / 维修保养 / 违章管理 | 车务数据岗、车务岗、财务、安全员、驾驶员 |
| 车辆资产安全 | 安全计划制定→安全培训→定期巡检→监控预警→风险事件处理→安全审计 | 安全管理岗、数据监控岗、运维岗、车务岗、驾驶员 |
| 车辆租售运营 | 订单发起→多级审核→合同签订→生成租售项目→租金催收→客户服务→退租处置 | 租售销售岗、部门管理员、法务、财务、车务岗、运维岗 |
| 数据归档 | 车辆全生命周期数据归档 | 车务数据岗 |

### 📦 管物流 — 新能源物流事业群全流程

覆盖 4 大阶段：

| 阶段 | 核心流程 | 涉及角色 |
|------|---------|---------|
| 物流业务承接 | 商机管理（录入→分级→跟进）→项目预立项（勘察→成本测算→毛利率评估→立项审批）→招投标→合同管理 | 市场专员、规划专员、部门负责人、财务专员、法务、总经理 |
| 物流业务运营 | 订单接收与确认→运力匹配与调度→车辆与司机准备→装货与交接→在途管理与监控→卸货与回单管理 | 客服专员、调度专员、车队长、驾驶员、驻场专员 |
| 结算 | 对账管理（磅单核对→生成对账单→客户确认）→结算与开票（生成结算单→盖章确认→开票） | 结算专员、财务专员、客服专员 |
| 收款 | 回款跟进→到账核销→逾期催收 | 财务专员、市场专员 |

### 数据流关键节点

- **磅单**：装货磅单 + 卸货磅单（司机拍照上传 → AI 识别 → 自动计算净重）
- **仪表盘**：里程数 + SoC（司机拍照上传 → AI 识别提取）
- **运输任务**：订单 → 调度拆分 → 多任务（多线路/多驾驶员）
- **对账**：任务级颗粒度 → 出入库确认单 → 结算单 → 发票 → 回款

## 四、五个 AI Agent 详细定义

| Agent | 定位 | 输入 | 输出 | 触发方式 |
|-------|------|------|------|---------|
| 🧠 调度 Agent | 运力调度副驾驶 | 矿场发运计划 + 历史运量 + 天气数据 + 可用车辆/司机 | 运力需求预测、派单策略推荐、异常调整建议 | 每日定时 + 订单变更事件 |
| 🛡️ 安全 Agent | 7×24 安全监督员 | 车载视频流 + 车辆状态监控数据（电池温度/过充过放/超速/GPS围栏） | 疲劳/分心实时预警、司机安全画像、安全周报 | 实时流式 |
| 💰 结算 Agent | 自动化结算会计 | 磅单识别结果 + 线路数据 + 合同结算规则 + 对账凭证 | 运单自动生成、费用计算、差异预警、结算单输出 | 订单完成事件 |
| 📊 资产 Agent | 资产管家 | 车辆台账 + 保险/年检/维保记录 + 里程/能耗/收入数据 | 到期预警、单车 ROI 计算、残值评估 | 定时轮询 + 事件驱动 |
| 🔗 数据 Agent | 数据连接器 | 智驭维科 API + 充电桩平台源码 + 飞书 API + Excel/手填表单 | 结构化数据、跨系统数据同步 | 定时同步 + 事件监听 |

### 人机协作边界

| Agent 负责 | 人负责 |
|-----------|--------|
| 数据采集、异常发现、模式预测、重复性操作、7×24 监控 | 采购决策、客户关系、例外处理、策略审批、现场执行 |

## 五、用户角色与权限体系

### 角色架构

```
                    ┌──────────────────────┐
                    │  总经办/总经理/董事长    │
                    │  全局决策 + 终审         │
                    └──────┬───────────────┘
                           │
          ┌────────────────┼────────────────┐
          │                                 │
  ┌───────┴──────────┐            ┌─────────┴──────────┐
  │ 车辆资产管理事业部   │            │ 物流业务运营部门      │
  │ 负责人（总经理+总监） │            │ 负责人（总经理+总监）  │
  └───────┬──────────┘            └─────────┬──────────┘
          │                                 │
  ┌───────┼───────┐                 ┌───────┼───────┐
  │       │       │                 │       │       │
  ▼       ▼       ▼                 ▼       ▼       ▼
车务岗  数据岗  安全岗           市场专员 调度专员 结算专员
运维岗  销售岗  监控岗           规划专员 车队长  客服专员
                                驻场专员 数据专员 驾驶员

          ┌──────────────────────────┐
          │  跨域共享角色              │
          │  财务专员 │ 法务专员 │ 人事专员 │
          └──────────────────────────┘
```

### 权限设计要点

- **数据隔离**：管车域与管物流域数据逻辑隔离，跨域查询需审批
- **多租户**：第三方供应商通过受限端口访问，仅可见自身承运订单
- **审批链**：支持多级审批（部门负责人 → 法务 → 财务 → 总经理）
- **移动端**：驾驶员 / 车队长 / 销售岗具有移动端（App 或小程序）操作权限

| 维度 | 要求 |

## 十、架构设计要点总结

1. **数据底座先行**：L2 数据底座是所有上层能力的基础，磅单 AI 识别与 IoT 数据采集是一期核心
2. **业务双域并行**：管车与管物流相对独立但共享车辆/司机/财务数据，需在 L4 数据服务层统一
3. **Agent 渐进增强**：一期先上结算 Agent + 数据 Agent（解决最痛结算问题），二期加强调度 Agent + 安全 Agent
4. **外部系统不推倒**：智驭维科平台作为车辆管理基础，本平台做增量补缺（结算 + AI + 充电桩打通）
5. **审批流可配置**：管车和管物流涉及大量审批流程，需通用审批引擎支撑
6. **移动端先核心后丰富**：一期司机端聚焦接单+磅单上传+报修，二期扩展考勤+报销+安全预警
